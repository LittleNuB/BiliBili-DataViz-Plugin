看过的视频会慢慢沉进历史记录，收藏夹也会越攒越多。Bili-Bill 把这些分散的信息留在本地，重新整理成可以查看、搜索和追问的个人资料。

| 看清时间花在哪里 | 找回收藏里的视频 | 追问正在看的内容 |
| --- | --- | --- |
| 查看本周、本月、连续观看时段与设备分布 | 用模糊描述搜索收藏，回答附带引用 | 生成摘要与亮点，用时间引用核对答案 |
| 每项统计显示实际覆盖日期和记录数 | AI 整理分类，本地索引负责候选范围 | 跳转时间点前先预览，再由用户确认 |

## 它怎样工作

<p align="center">
  <strong>同步历史与收藏</strong> →
  <strong>本地去重与索引</strong> →
  <strong>账单、搜索与问答</strong> →
  <strong>用户核对来源</strong>
</p>

AI 只在用户主动触发时参与分类、整理与问答。入选、排序、状态推进和数据清理由本地规则负责。数据没有覆盖到的地方会留下空白，早期历史、未采到的播放时长和缺少可靠正文的视频不会被补成完整结论。

## 三步开始使用

1. 在同一个浏览器 Profile 登录 B站，安装扩展并打开持久小窗。
2. 手动同步当前账号可获取的历史记录和收藏夹。
3. 打开完整面板查看账单，或在收藏与当前视频页面使用搜索、摘要和问答。

## AI 在哪里工作

### 智能收藏

智能收藏先把标题、简介、UP 主和原收藏夹等元数据保存到本地，再生成分类路径、摘要、关键词和可检索别名。搜索与问答会先跑本地预筛选，模型只能使用送入候选集的内容组织回答。

模型服务不可用时，本地收藏与索引仍然留在浏览器里。Bili-Bill 不会创建、移动、删除或重命名 B站原收藏夹。

### 当前视频助手

当前视频助手使用默认关闭的完整文本授权。打开开关本身不会发送内容，打开页面、切换视频和恢复会话也不会自动请求模型。只有用户点击生成或提交问题后，当前分 P 的可靠主要文本才会发送到用户配置的 AI 服务。

摘要、亮点和问答都绑定当前视频、分 P 与具体文本版本。亮点时间必须来自真实时间行，问答引用必须能映射回同一份文本。任何一个引用无法核对时，本次结果会整体拒绝显示。

### 动态账单

动态账单固定展示被淹没的关注、收藏关联更新和关注轮换。它帮助用户重新看到近期消费里安静下来的关注关系。候选资格、栏目分配、轮换与负反馈由本地证据和确定性规则决定，AI 不能把它改成点击概率排序。

少提醒某位 UP 主会在本地暂停 30 天，可以立即撤销或在设置里恢复。这个动作不会修改 B站关注关系。

## 当前能力

### 个人内容账单

- 使用 B站历史接口 `/x/web-interface/history/cursor` 读取当前账号可获取的跨设备历史。
- 使用本机 `playerEvents` 修正扩展运行后的 PC 播放时长、连续观看天数和设备分布。
- IndexedDB 默认保留最近 90 天数据，支持全量同步、增量同步、取消与数量上限。
- 面板展示自然周、自然月、命中记录数、本地覆盖范围、当前连续时段与历史最长连续时段。
- 本地历史可以导出为 JSON 或 CSV。

### 智能收藏与视频助手

- 同步 B站收藏夹的当前完整快照，并清理 B站端已经删除或移出的项目。
- 生成 AI 分类树，支持分类下钻、自然语言搜索和引用式问答。
- 查看、搜索并导出 B站字幕正文，支持 TXT 与 SRT。
- 当前视频摘要与亮点使用当前分 P 的完整主要文本，问答先给答案再列引用。
- 问答会话保存在本地，切换视频后仍能阅读旧回答；新问题只使用提交时绑定的视频证据。

### 兴趣再平衡与探索

- 动态账单保留固定三栏和明确入选理由，也支持暂停、撤销、恢复与一次性低压力取关提示。
- 视频盲盒包括随机探索、跨区漫游、冷门收藏和 UP 主考古，每张卡都会说明候选从哪里来。
- 设置页统一管理 AI 开关、本地数据状态、分类清理、全部清理与诊断导出。

## 安装

### 使用预发布包

1. 从 [Releases](https://github.com/LittleNuB/BiliBili-DataViz-Plugin/releases) 下载 `bili-bill-0.13.0-alpha.zip`。
2. 解压到单独目录。
3. 在 Chrome 或 Edge 的扩展管理页打开开发者模式。
4. 点击加载已解压的扩展程序，选择包含 `manifest.json` 的目录。

GitHub 的 Code 下载项只包含源码，不包含构建后的 `dist` 目录。

### 从源码构建

```bash
npm ci
npm run build
```

随后在扩展管理页加载项目的 `dist` 目录。代码更新后，需要重新运行构建并点击重新加载。

当前 npm 包版本为 `0.13.0-alpha`。Chrome MV3 Manifest 使用 `version` 值 `0.13.0`，并通过 `version_name` 显示预发布标识。

## 数据口径

- 本周从周一零点算到当前可用数据，本月从当月第一天零点算起。
- B站历史记录里的 `progress` 是跨设备估算字段，不能当成真实播放时长。
- 本机 PC 播放时长来自扩展运行后的播放器心跳和播放事件。
- 同日同视频同时存在 B站历史与本机事件时，优先使用本机实测，避免重复计数。
- 连续观看天数同时参考 B站历史记录和本机有效播放日期，并显示真实起止日期。
- 智能收藏只使用收藏视频元数据，不下载视频、不分析画面。

## 同步怎样进行

首次同步或手动刷新会从 cursor 首页开始翻页，用户可以选择最多 10、50、100 或 300 页，对应大约 300、1500、3000 或 9000 条记录。日常后台同步每 5 分钟运行一次，碰到本地已有边界后停止。

去重键使用 `sessionKey = kid:viewAt`，同一视频在不同日期观看时会保留不同记录。同步锁会拦住重复点击产生的并发写入，停止按钮也会取消当前请求与后续等待。

## 隐私边界

- 完整历史、收藏列表、关注列表、反馈记录、Cookie、账号标识和个人资料不会整库上传给第三方。
- 扩展不会读取本地 Cookie 文件、密钥文件、浏览器 Profile 文件或 B站登录态文件。
- 当前视频助手只有在用户主动开启授权并提交生成或提问后，才会发送当前分 P 的完整主要文本。
- 动态账单与智能收藏只使用各自完成任务所需的最小上下文，不会继承当前视频的完整文本权限。
- 扩展不会写回关注关系，也没有自动取关或批量修改关注设置的能力。
- 配置与问答会话默认保存在本地。API Key 只会随用户主动发起的 AI 请求交给其配置的服务，界面不会回显完整值。

## 已知限制

- B站接口返回范围由 B站决定，扩展无法补回接口不再提供的历史。
- 默认只保留最近 90 天观看历史，暂不提供保留天数设置入口，也不承诺长期或无限归档。
- 扩展安装前的本机 PC 心跳无法补回。
- B站 AI 字幕尚未进入播放器时，需要用户先在播放器里手动开启中文 AI 字幕，再重新检测。
- `0.13.0-alpha` 没有本地语音转录、画面理解、OCR、说话人分离或多视频全文综合问答。
- AI 能力依赖用户提供的 OpenAI 兼容 API Key。共享浏览器设备上的本地密钥需要由使用者自行评估风险。
- 这是 GitHub 预发布版本，没有经过 Chrome Web Store 审核，也没有上架。
