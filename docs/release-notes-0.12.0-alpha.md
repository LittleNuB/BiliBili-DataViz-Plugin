# Bili-Bill 0.12.0-alpha 内测发布说明

说明日期：2026-06-22

`0.12.0-alpha` 是面向内测用户的已解压扩展内测版。它聚焦“内容助手”主线：统一设置入口、当前视频页内 Agent、当前视频相关收藏、视频盲盒候选来源边界，以及 Smart Favorites 知识库的产品规划。

本说明基于当前 `main` 和 0.12 集成 QA 报告整理。它只说明内测范围、安装升级、隐私边界和已知限制；不代表已经发布 GitHub Release、商店包或压缩包。

## 本次重点

### 设置页：AI 与本地数据统一入口

- Dashboard 新增统一设置入口，用来配置 OpenAI 兼容服务地址、模型名称和 API Key。
- 当前视频、智能收藏、动态账单等功能的 AI 开关集中在设置页管理。关闭或未配置时，对应功能应继续展示本地证据结果，而不是让用户在各功能页重复配置。
- 设置页提供隐私说明和本地数据入口，包括刷新状态、清理当前视频字幕缓存、重建智能收藏索引和清理本地数据。危险操作需要二次确认。
- API Key 保存在浏览器本地存储中；保存状态会显示，但不会在普通界面反复展示完整内容。

### 当前视频 Agent：先回答，再给证据片段

- 在 B 站视频页内，当前视频 Agent 可以围绕正在看的视频提问，并基于当前视频证据生成回答。
- 查询会先做本地改写和同义表达扩展，例如中英文 AI 概念、连字符、数字单位和常见表达变体，减少“词不同但意思相近”导致的漏找。
- 回答会附带可跳转的引用片段。片段只来自当前视频的可用证据，不会凭空生成时间点。
- 跳转仍是手动闭环：先预览，不改变播放位置；用户确认后才跳到片段；跳转后可以返回原位置。
- 如果真实页面没有可用字幕正文，Agent 会说明只能使用标题、简介、分 P、章节或本地可用的有限线索，不能把有限信息写成完整视频理解。

### 当前视频相关收藏

- 当前视频 Agent 可以单独展示“相关收藏”分区，帮助用户从当前已同步收藏里找相近主题的视频。
- 相关收藏不属于当前视频回答的证据。当前视频问题仍只由当前视频证据回答。
- 如果收藏同步不完整，界面和回答都应限定为“当前已同步收藏”，不能暗示已经检查了全部收藏。
- 打开相关收藏只会跳到 B 站视频页，不会写回收藏夹或改变 B 站数据。

### Smart Favorites 知识库状态

- 0.12 已整理 Smart Favorites 知识库 PRD 和边界：目标是把“本地收藏检索 + 引用视频 + 可选 AI 整理”收束成可追溯的收藏问答体验。
- 当前可验证的是已有本地收藏问答、引用视频、同步覆盖提示，以及当前视频里的相关收藏联动边界。
- 完整“个人视频知识库”仍处在规划和后续切片阶段。它不应被理解为已经完整上线的跨视频正文问答能力。
- 第一版知识库边界仍是当前已同步收藏和本地智能索引；不分析字幕、弹幕、评论、音频、画面或完整视频正文。

### 视频盲盒：真实候选和本地候选分清楚

- 随机探索：使用少量本地公开视频作为种子，请求公开相关视频候选池，再在本地随机抽取。它的候选应标注为真实 B 站候选。
- 换口味：先用本地长期兴趣和近期低频方向选择探索方向，再从 B 站公开分区新视频候选池抽取。它不是从本地收藏里凑一条。
- 冷门收藏：只回访本地收藏，来源应明确写成本地收藏，不冒充真实 B 站候选。
- 本地兴趣回顾 / 长期兴趣回顾：只基于本地观看历史做回看提示，不读取关注新投稿，也不替代 Dynamic Bill 的兴趣再平衡。
- 候选源不可用时，盲盒应展示原因和重试入口；没有真实候选时，不用本地库存冒充外部探索。

### Dynamic Bill 定位

Dynamic Bill 在本版本仍只按“兴趣再平衡”理解和表达：帮助用户看见长期兴趣、近期冷却方向和被近期口味覆盖的已关注内容线索。0.12 的内容助手更新没有改变这个定位。

## AI 与隐私边界

- AI 是可选增强。未配置、关闭或请求失败时，核心本地证据结果仍应可见。
- AI 请求只发送当前功能所需的最小上下文，例如当前视频的有限证据片段、当前已同步收藏的少量引用视频，或单条动态账单项目的紧凑证据。
- 不上传完整观看历史、完整收藏、完整关注、完整反馈记录或完整本地数据库。
- 不读取本地 Cookie 文件、浏览器用户资料目录、B 站登录态文件、密钥文件或本地密钥路径。
- 不写回 B 站；不会关注、取关、移动收藏、删除收藏、评论、点赞、投币或修改播放状态。
- 需要登录态的数据同步只能由用户在扩展运行时主动触发。开发和 QA 不从磁盘提取登录凭据。

## 安装与升级

0.12.0-alpha 仍按已解压扩展方式内测。

1. 使用测试用浏览器环境，并按需在浏览器中登录 B 站。
2. 切换到发布负责人指定的 0.12.0-alpha 代码或构建来源。
3. 安装依赖并构建：

   ```bash
   npm install
   npm run build
   ```

4. 打开 Chrome 或 Edge 的 `chrome://extensions`。
5. 开启“开发者模式”。
6. 首次安装时点击“加载已解压的扩展程序”，选择项目 `dist/` 目录。
7. 已安装开发版时，在扩展卡片上点击“重新加载”。
8. 打开 Popup 或 Dashboard，按需同步历史、收藏或动态账单数据；涉及 B 站登录态的数据同步只通过扩展运行时发起。

## 已知限制

- `0.12.0-alpha` 是内测版本，不是 Chrome Web Store 正式发布包。
- 本发布说明任务不创建 tag、不发布 GitHub Release、不生成 zip 或 crx、不修改 manifest 或版本元数据。
- 真实 B 站页面在未登录临时会话下可能拿不到字幕正文地址。0.12 集成 QA 已验证无字幕正文时的降级说明、问答提交和预览/确认/返回跳转；如需真实账号字幕正文端到端覆盖，需要发布负责人明确批准并由用户手动完成登录会话准备。
- `npm ci` 在 0.12 集成 QA 中仍报告 1 条高严重级别依赖审计提示；本轮未改依赖，是否作为发布门禁由发布负责人单独判断。
- 生产构建仍会输出既有 Vite dynamic-import / chunk-size warnings；集成 QA 中 `npm run build` 已完成，这些 warning 当前不作为功能阻塞。
- Smart Favorites 知识库仍是规划和后续实现切片，不是完整跨视频正文知识库。
- 视频盲盒真实候选源依赖 B 站公开接口可用性；来源不可用时应清楚降级，不显示空卡或混淆来源。

## 内测反馈建议

- 设置页：AI 配置、功能开关和本地数据入口是否容易找到；隐私边界是否说得清楚。
- 当前视频 Agent：回答是否先说明结论，再给可验证片段；预览、确认和返回是否容易理解。
- 相关收藏：是否能看出它只来自当前已同步收藏，且没有混入当前视频回答证据。
- Smart Favorites：知识库规划是否符合你对收藏问答的期待；现有引用视频和覆盖提示是否足够可信。
- 视频盲盒：随机探索、换口味、冷门收藏和本地兴趣回顾的来源是否容易区分；真实 B 站候选和本地候选是否标注清楚。
- Dynamic Bill：是否仍能理解它是兴趣再平衡。
