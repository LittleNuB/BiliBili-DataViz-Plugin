# Bili-Bill 当前视频 Agent v2 PRD

## 1. 背景

当前视频页内助手已经能在真实 B 站页面完成字幕正文缓存、字幕证据摘要、片段检索、预览跳转、确认跳转、返回原位置和知识节点展示。这个阶段解决了“能拿到证据、能跳到证据”的问题。

但用户反馈显示，现有体验仍像“字幕检索器”：

- 输入自然语言问题时，系统只做片段检索。
- `子代理` 和 `subagent` 这类同义概念无法互相召回。
- 系统不会先回答问题，再给证据片段。
- 用户需要自己从候选片段里判断答案。

v2 的目标是把当前视频助手升级为真正的 **当前视频 Agent**：用户可以边看视频边提问，Bili-Bill 先基于当前视频证据回答，再给出可跳转片段。

## 2. 产品定位

当前视频 Agent 是当前 B 站视频页内的本地证据助手。它只回答当前视频相关问题，所有回答必须引用当前视频的可用证据。

它不是全站搜索，不是 B 站推荐系统，不是通用聊天机器人，也不是跨视频知识库。

## 3. 核心用户问题

- 这个视频有没有讲某个概念？
- 某个概念大概在哪个时间点出现？
- 视频里对某个主题的结论是什么？
- 我想跳到讲某个内容的片段。
- 没有字幕时，为什么不能完整回答？

## 4. MVP 范围

v2 必须完成三件事：

1. 查询改写和同义词扩展。
2. 当前视频问答 v1。
3. 页内助手 UX polish。

### 4.1 查询改写和同义词扩展

目标：解决词面不一致导致的检索失败。

必须支持：

- 中英同义词：`subagent`、`sub-agent`、`子代理`、`子智能体`、`多代理`、`multi-agent`。
- 常见 AI 概念：`context window`、`上下文窗口`、`长上下文`、`1M context`、`100万上下文`、`一兆上下文`。
- 常见表达变体：大小写、连字符、空格、数字单位。

第一版优先使用本地词表和规则，不强依赖 embedding。

输出应包含：

- 原始 query。
- 扩展 query terms。
- 命中原因。
- 是否启用 AI query rewrite。

### 4.2 当前视频问答 v1

输入示例：

- “有没有关于 subagent 的介绍？”
- “这个视频怎么解释 100 万上下文？”
- “讲工具调用的地方在哪里？”
- “作者对 Agent 能力提升的结论是什么？”

输出结构：

- 回答状态：有证据、没有找到、证据不足、字幕不可用。
- 一段自然语言回答。
- 证据片段列表，最多 3-5 条。
- 每条证据包含时间范围、字幕文本、证据强度、操作按钮。
- 操作按钮继续使用预览跳转、确认跳转、返回原位置。

回答必须遵守：

- 只基于当前视频字幕正文、当前视频知识节点、标题、简介、分 P、章节等证据。
- 没有字幕正文时不能声称完整理解视频。
- 没有证据时要说“当前视频证据里没有找到”，不能编答案。
- AI 不能生成新时间点；时间点只能来自本地候选或知识节点。

### 4.3 页内助手 UX polish

当前面板包含摘要、提问定位、知识节点。v2 需要让它更像一个助手，而不是堆叠模块。

建议结构：

- 顶部：视频身份、字幕状态、重新检测。
- 主输入框：问这个视频，或描述想跳到的片段。
- 结果区：
  - 回答。
  - 引用片段。
  - 跳转操作。
- 辅助区：
  - 摘要。
  - 知识节点。

必须修正：

- “正文文本不可用”和“字幕正文已缓存”的混淆。
- `fallback`、`confidence`、`transcript` 等工程化英文不得出现在普通用户 UI。
- 跳转后状态保持清楚：已跳到哪里、可返回哪里。

## 5. 非目标

本版本不做：

- 跨视频问答。
- 用收藏夹或历史记录回答当前视频问题。
- 全站搜索。
- 自动跳转。
- AI 生成不存在的时间点。
- 基于画面 OCR 或音频识别的内容理解。
- 长期对话记忆。
- 上传完整字幕全文给 AI。

## 6. 数据与证据边界

允许使用：

- 当前视频标题、UP 名称、BVID、CID、分 P、时长。
- 当前视频简介。
- 当前视频字幕正文的有限片段。
- 当前视频知识节点。
- 本地检索候选和证据强度。

不允许使用：

- 完整观看历史。
- 完整收藏列表。
- 完整关注列表。
- Cookie、浏览器 profile、本地 key 文件。
- 用户 mid、UP mid 等非必要个人标识。
- 与当前视频无关的本地数据库记录。

## 7. AI 角色

AI 可以做：

- 把用户问题改写成更适合检索的 query。
- 在本地候选片段中选择最相关的证据。
- 根据候选证据组织回答。
- 给出“证据不足”的自然语言解释。

AI 不可以做：

- 创造候选片段。
- 发明时间点。
- 引用未提供的字幕或外部知识。
- 绕过低置信、过期、视频身份不匹配等本地 guard。
- 让用户直接跳转而不走确认流程。

## 8. 回答状态

建议状态：

- `answered`：有明确证据并已回答。
- `partial`：有相关证据，但不足以完整回答。
- `not_found`：当前视频证据中没有找到。
- `no_transcript`：当前视频没有可用字幕正文，只能使用简介/元数据。
- `low_confidence`：候选片段过弱，不建议跳转。
- `ai_unavailable`：AI 未配置、未启用或失败，显示本地证据结果。

普通 UI 必须使用中文文案，不展示状态码。

## 9. 成功标准

用户输入“有没有关于 subagent 的介绍？”时：

- 如果字幕中有“子代理/子智能体/多 Agent”相关内容，应能召回。
- 回答先说明“有/没有/证据不足”。
- 证据片段可预览和确认跳转。

用户输入“讲工具调用的地方在哪里？”时：

- 应返回工具调用相关片段，而不仅搜索字面完全相同的词。

无字幕时：

- 明确提示无法完整回答。
- 不伪造时间点。

## 10. 风险

- 规则词表过窄，仍无法覆盖用户表达。
- AI query rewrite 可能引入不相关词。
- AI 回答可能过度概括。
- 当前视频字幕 ASR 误识别会影响结果，例如 `1M` 被识别为相近中文词。
- 面板内容变多后遮挡播放器。

## 11. 待验证假设

- 本地同义词扩展能解决 60% 以上的中英概念召回问题。
- 用户更需要“先回答，再给片段”，而不是只看候选列表。
- AI 只基于 top N 证据片段组织回答，质量足够。
- 面板内三块信息改造成回答优先后，用户不会迷失在摘要、知识节点和检索结果之间。
