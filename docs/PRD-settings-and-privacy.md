# Bili-Bill 设置与隐私 PRD

## 1. 背景

Bili-Bill 早期把 AI Key 放在智能收藏页，是因为 AI 最先只服务收藏索引。现在 AI 已经被当前视频摘要、当前视频问答、智能收藏问答、动态账单解释和后续视频盲盒增强共同使用。继续把 AI 配置放在智能收藏页，会让用户误以为 AI 只是收藏功能的一部分，也会让后续模型选择、功能开关、隐私说明和本地数据管理缺少统一入口。

设置页的目标是把全局能力从功能页中抽离出来，让用户在一个地方完成 AI 配置、本地数据管理和隐私边界确认。

## 2. 产品定位

**设置** 是 Bili-Bill 的全局配置中心，负责管理 AI 服务、本地数据、隐私说明和诊断入口。

它不是新功能页，不承载内容消费或分析结果；它回答的是：

- 我有没有配置 AI？
- AI 会被哪些功能使用？
- 我的 API Key 存在哪里？
- 哪些数据只保存在本地？
- 如何重建索引、清理缓存或导出诊断？

## 3. 目标用户

- 第一次使用 Bili-Bill，需要配置 AI 和理解隐私边界的用户。
- 已经使用智能收藏、动态账单和当前视频助手，希望统一管理 AI 开关的用户。
- 需要排查同步、索引或字幕缓存状态的用户。
- 对 API Key、本地数据和上传边界敏感的用户。

## 4. 核心场景

### 4.1 配置 AI

用户进入设置页，填写 OpenAI-compatible Base URL、模型名和 API Key，点击测试连接。测试成功后，当前视频助手、智能收藏问答、动态账单解释等功能可以复用同一套配置。

### 4.2 管理功能级 AI 开关

用户可以分别控制：

- 当前视频摘要与问答。
- 当前视频片段 AI 重排或回答整理。
- 智能收藏问答。
- 动态账单解释。
- 后续视频盲盒增强。

关闭某个开关时，对应功能必须显示本地证据 fallback，而不是报错。

### 4.3 查看隐私边界

用户能看到清楚说明：

- API Key 仅保存在本地浏览器存储中。
- 不读取 Cookie 文件、浏览器 profile 或本地 key 文件。
- 不上传完整观看历史、完整收藏、完整关注或 feedback 记录。
- AI 请求只发送当前功能需要的最小证据片段。
- 不写回 B 站关注关系、收藏夹或视频数据。

### 4.4 管理本地数据

用户可以从设置页触发或查看：

- 观看历史同步状态。
- 收藏夹同步状态。
- 智能收藏索引状态。
- 当前视频字幕缓存状态。
- 动态账单数据状态。
- 清理当前视频字幕缓存。
- 重新生成智能收藏索引。
- 清理全部本地数据。

危险操作必须二次确认。

## 5. MVP 范围

v1 设置页必须包含：

- Dashboard 侧边栏新增一级入口：设置。
- 设置页副标题：AI 与本地数据。
- AI 服务配置：Base URL、模型名、API Key、测试连接。
- API Key 保存状态，不明文重复展示完整 key。
- AI 功能开关：当前视频、智能收藏、动态账单。
- 隐私边界说明。
- 本地数据管理入口：重新生成智能收藏索引、清理当前视频字幕缓存、清理全部本地数据。
- 智能收藏页中的 AI 配置迁移提示。
- 当前视频助手、智能收藏、动态账单遇到 AI 未配置时，统一提示前往设置。

## 6. 非目标

本版本不做：

- 多套 AI provider profile。
- 云端同步配置。
- 用量计费统计。
- API Key 加密同步到远端。
- 自动读取系统环境变量或本地 key 文件。
- 商店级 OAuth 或第三方账号登录。
- 复杂权限面板，例如逐字段选择 AI payload。

## 7. 信息架构

建议设置页分为四块：

### 7.1 AI 服务

字段：

- 服务地址。
- 模型名称。
- API Key。
- 测试连接按钮。
- 最近一次测试结果。

用户可见文案：

- “API Key 只保存在本地浏览器，不会提交到 Bili-Bill 服务器。”
- “如果使用自定义服务地址，浏览器可能要求授权该域名的网络访问权限。”

### 7.2 AI 功能开关

开关：

- 当前视频助手。
- 当前视频问答增强。
- 智能收藏问答。
- 动态账单解释。
- 视频盲盒增强。

开关文案要描述用途，不展示内部 action 名。

### 7.3 本地数据

展示：

- 历史记录：已同步条数、覆盖范围、最后同步时间。
- 收藏夹：B 站报告数、本地保存数、已索引数。
- 当前视频：字幕缓存条数和最近缓存时间。
- 动态账单：最后生成时间。

操作：

- 重新同步历史。
- 重新同步收藏夹。
- 重新生成智能收藏索引。
- 清理当前视频字幕缓存。
- 清理全部本地数据。

### 7.4 隐私与诊断

展示：

- 数据最小化说明。
- AI payload 边界说明。
- 本地数据存储位置说明。
- 导出诊断信息按钮。

诊断导出不得包含：

- API Key。
- Cookie。
- 浏览器 profile 路径。
- 完整历史、完整收藏、完整关注、feedback 原始记录。

## 8. 迁移要求

### 8.1 智能收藏页

智能收藏页不再显示完整 AI 配置表单。

保留：

- AI 状态摘要。
- “前往设置配置 AI”按钮。
- 智能索引状态。

### 8.2 当前视频助手

AI 未配置或未启用时：

- 当前视频摘要走本地证据结果。
- 问答增强显示“需要在设置中启用 AI 才能整理回答；仍可查看本地证据片段”。
- 不跳到智能收藏页。

### 8.3 动态账单

AI 未配置或未启用时：

- 展示本地证据版账单。
- 提示“可在设置中启用 AI 解释”。

## 9. 成功指标

- 用户能在 30 秒内找到 AI 配置入口。
- 用户不再从智能收藏页理解 AI 是收藏专属配置。
- 当前视频、智能收藏、动态账单的 AI 未配置提示都指向同一个设置入口。
- 清理字幕缓存和重新生成收藏索引可以从设置页找到。
- 用户可复述“Bili-Bill 不读取 Cookie 文件、不上传完整历史或收藏”。

## 10. 风险

- 设置页范围容易膨胀成运维面板。
- 功能开关过多会让用户困惑。
- “清理全部本地数据”误触风险高。
- 自定义 Base URL 的 host permission 失败需要清楚解释。

## 11. 待确认问题

- API Key 是否需要提供“显示/隐藏”完整 key 的按钮。
- 是否保留 DeepSeek 默认模板。
- 是否在设置页展示 AI 请求示例 payload。
- 清理全部本地数据是否需要输入确认文字。
- 是否把“导出 JSON/CSV”也迁入设置，还是继续保留在 Dashboard 顶部。
