# Bili-Bill 0.13 设置与隐私 PRD

> 0.13 实现与验收以 [`PRD-0.13-release-contract.md`](./PRD-0.13-release-contract.md) 为单一有效合同。本文件定义设置页的详细状态、迁移和本地数据管理规则。

## 1. 产品定位

设置页是 Bili-Bill 的全局配置、授权、本地数据和隐私中心。它不承载内容消费结果，也不要求用户理解内部 action、缓存键、内容哈希或数据库表。

设置页回答四类问题：

1. 当前使用哪一个 AI 服务，连接是否可用。
2. 哪些 AI 能力已经由用户主动开启。
3. 哪些本地数据和模型占用空间，如何单独清理或恢复。
4. 数据何时保持本地、何时会发送给用户配置的服务。

## 2. 信息架构

设置页保持四个全宽区域：

1. AI 服务。
2. AI 功能开关。
3. 本地数据与恢复。
4. 隐私与诊断。

普通用户文案使用自然中文，不显示原始错误、内部字段、数据库名称或本地路径。

## 3. AI 服务

### 3.1 配置字段

- 服务地址。
- 模型名称。
- API Key。
- 测试连接。
- 最近一次测试结果。

### 3.2 保存与展示

- API Key 只保存在浏览器扩展本地存储，不提交给 Bili-Bill 自有服务器。
- 已保存的完整 Key 不回填到输入框，不提供明文完整展示按钮。
- 用户留空 Key 并保存时保留现有 Key；只有明确执行“移除 Key”才删除。
- 自定义服务地址需要额外 host permission 时，在用户操作后请求并用中文说明结果；拒绝权限不修改已保存配置。
- 测试连接只发送最小健康检查消息，不包含历史、收藏、关注、反馈、字幕、转录稿或其他本地内容。

## 4. AI 功能开关

0.13 只保留三个开关：

### 4.1 当前视频 AI 助手

- 默认关闭。
- 同时控制摘要、亮点和当前视频问答，并承担“允许 AI 使用当前分 P 完整主要文本”的授权。
- 开启开关本身不发送请求；只有用户生成摘要与亮点或提交问题时才发送。
- 开关旁说明发送范围是当前分 P 的主要文本，不包括音频、其他分 P、评论、弹幕、历史、收藏或关注关系。
- 关闭后停止新的摘要、亮点和问答请求，并使仍在进行的当前视频 AI 请求失效、尽力中止网络请求；迟到响应不落库。关闭不删除已有结果、问答会话、字幕或本地转录稿。
- 字幕页的查看、搜索、导出和确认跳转不依赖该开关。

### 4.2 智能收藏问答

- 默认关闭。
- 只允许 AI 基于本地预筛后的少量收藏引用生成综合回答。
- 关闭、未配置或失败时继续展示本地引用结果，不改变收藏索引。

### 4.3 动态账单解释

- 默认关闭。
- 只允许 AI 为已经由本地规则入选的账单项生成摘要和解释。
- AI 不参与入选、栏目归属、轮换顺序、状态变化、30 天暂停或取关提示。
- 关闭、未配置或失败时继续展示完整的本地证据版账单。

### 4.4 不存在的开关

- 不保留“当前视频片段排序辅助”或独立“当前视频问答整理”开关。
- 不为摘要和亮点分别设置开关。
- 视频盲盒不设置 AI 开关；四类候选和随机抽取由本地规则与真实 B 站候选源完成。
- 本地转录不是 AI 聊天开关。它只在当前视频字幕页由用户主动启动，并使用独立的确认、模型和清理流程。

## 5. 升级与状态一致性

- 从 0.12 升级到 0.13 时保留有效的服务地址、模型名和已保存 API Key。
- 不根据旧的摘要、片段重排或问答开关自动开启“当前视频 AI 助手”；用户必须重新主动授权完整文本。
- 旧开关迁移完成后不再参与运行时判断，也不在普通 UI 展示。
- 保存设置后，Dashboard、当前视频助手、智能收藏和动态账单都从同一份持久配置读取状态。
- 页面切换、刷新或重新打开 Dashboard 时，开关 UI 必须显示实际持久状态，不得只依赖组件内临时状态。
- 保存失败时保留用户当前输入并显示中文错误，不得让界面显示已保存但运行时仍使用旧值。

## 6. 本地数据与恢复

设置页只展示数量、覆盖范围、最近时间和占用空间，不展示完整记录、敏感标识或本地文件路径。

### 6.0 数据类别生命周期合同

- `SET-013-A` 先定义共享的数据类别注册接口；任何后续切片新增持久数据时，都必须在同一切片登记自然中文类别名，并实现数量/占用统计、内部独立清除 hook、清除后实际回读和“清理全部本地数据”挂接。
- 清除接口必须只操作本类别拥有的数据。跨类别依赖由调用方显式编排，不能通过级联删除悄悄清除字幕、转录稿、生成结果、会话、模型或设置。
- 每个清除操作返回成功、部分失败或失败类别；设置页只显示自然中文类别和可重试状态，不展示表名、主键、内部字段或原始异常。
- `SET-013-B` 只负责汇总已经登记的类别、展示计数并编排清除；不得在最后阶段直接读取各功能表来反推统计或清理规则。
- 新增持久数据但没有同时交付 count/clear/readback hooks 的功能切片不得合并。
- 内部独立清除 hook 是生命周期能力，不自动产生用户可见按钮。只有本 PRD 明确列出的类别提供单独清理入口；其余类别仍必须可由“清理全部本地数据”逐类调用和回读。
- 已列出的单独清理入口以注册类别的真实数量或占用任一非零为可用依据；即使只剩同步状态、筛选状态或字幕来源记录等本地元数据，也必须允许清理并回读为零。

### 6.1 历史与收藏

展示：

- 观看历史：已同步条数、实际覆盖范围、最后成功同步时间。
- 收藏夹：已同步收藏夹数、视频数、智能索引数和最后同步时间。

同步进行中或覆盖不完整时仍展示最后一次成功同步时间，并另行说明当前同步或覆盖状态，不能用状态提示替代最近时间。

操作：

- 重新同步历史。
- 重新同步收藏夹。
- 重新生成智能收藏索引。
- 清除本地观看历史；历史同步进行中时不可执行。
- 清除本地收藏快照与智能索引。

清除操作只删除 Bili-Bill 的本地副本，不修改 B 站历史或收藏夹。不得把当前可用记录数量描述为 B 站完整历史或完整收藏覆盖。

历史同步、历史清理、播放器事件写入与统计聚合共用历史数据操作门禁。已经开始的播放器事件和统计聚合先完成再清理；历史清理及其回读期间不接收新的播放器事件或聚合写入，统计聚合不读取同步中的半成品历史，历史同步与清理互斥，避免清理完成后被迟到事件、聚合或同步结果恢复本地记录。

清理本地设置时，后台必须在一次存储写入中把 `userConfig` 替换为无内容的清理标记并推进配置变更代次；只有这一已确认的配置变更事件才让所有已打开的设置页清除旧密钥状态和功能开关，单独的代次事件不得显示“已清理”。每次保存前还必须重新读取后台当前配置并与本页最后观察状态核对，后台再串行执行完整的读取、核对与写入，并同时核对变更代次；缺少完整期望快照的写入直接拒绝，清理即使面对空配置也会推进代次。如果其他页面已经清理或更新，本次保存中止并刷新表单，避免并发页面、事件回调迟到、清理前后配置内容恰好相同或清理恰好发生在预读之后时把旧配置重新写回。清理标记和代次都不包含 Key、开关或正文，不计入用户数据和诊断导出，仅作为清理边界保留。清理接口已经完成回读后，页面必须保留成功或部分失败回执；后续页面状态刷新失败只能追加提示，不能把已经完成的清理显示为失败。

收藏同步、智能索引生成、收藏清理与“清理全部本地数据”共用收藏数据操作门禁。已经开始的同步或索引先完成再清理；清理期间的新同步或索引等待清理及回读结束，避免迟到写入恢复已清除数据。

### 6.2 当前视频文本

分别展示：

- 已缓存的 B 站字幕正文：去重后的视频/分 P 数、内部字幕来源身份数、片段数、UTF-8 序列化占用和最近更新时间；上限为 50 个字幕来源身份或 50 MB，按最久未访问顺序清理。
- 正式 ASR 实现实际存在时，才展示已完成的本地转录稿分 P 数、序列化占用和最近更新时间。
- 正式 ASR 实现实际存在时，才展示本地转录模型是否已下载、准确体积和版本说明。

分别提供：

- 清除 B 站字幕正文缓存。
- 正式 ASR 实现实际存在时，才提供清除本地转录稿。
- 正式 ASR 实现实际存在时，才提供清除本地转录模型。

当前 0.13 no-go 主线没有本地转录稿或模型生产者，因此设置页不展示这两类计数或清理入口。未来正式实现进入主线后，三项仍须互不连带：清除模型不删除已完成转录稿；清除转录稿不删除模型或 B 站字幕。

单个 B 站字幕来源超过 50 MB 时不进入持久统计，也不驱逐其他缓存；它只在当前页面运行时内存中临时使用，离页后释放。设置页不把临时正文计为已缓存数据。

### 6.3 视频助手生成结果

分别展示：

- 摘要与亮点缓存：分 P 数、占用空间、最近生成时间；上限为 50 个分 P 或 5 MB。
- 问答会话：会话数、占用空间、最近使用时间；上限为 200 个会话或 25 MB。

分别提供：

- 清除摘要与亮点缓存。
- 清除全部问答会话。

清除生成结果不删除字幕正文、本地转录稿、转录模型或 AI 服务配置。

### 6.4 动态账单

展示：

- 最近一次同步和账单生成时间。
- 当前账单项数量。
- 30 天暂停中的 UP 主数量。

一次账单生成即使得到 0 项，也必须保留这次成功生成的时间；该时间属于动态账单本地数据，清理动态账单时一并删除。

提供暂停中的 UP 主列表，列表只显示自然名称和暂停到期日期，并提供逐项“恢复提醒”。恢复后从下一次账单生成起按普通证据和全局轮换参与，不获得额外优先级。

提供“清除动态账单”入口，删除本地关注快照、近期投稿、账单项、解释、反馈、暂停和轮换状态；不修改 B 站关注关系。

动态账单同步、生成与清理共用本地数据操作门禁。已经开始的同步先完成再清理；清理期间新同步等待到清理及回读结束，避免清理成功后被迟到写入重新生成本地数据。

设置页不提供取关操作，也不修改 B 站关注关系。

### 6.5 视频盲盒

展示最近抽取记录数量，最多 50 个 BV。该类别提供内部独立 clear/readback hook，供测试和“清理全部本地数据”逐类调用；0.13 不提供独立去重开关或单独清理按钮。

## 7. 清理全部本地数据

- “清理全部本地数据”必须经过二次确认。
- 确认框列出将删除的主要类别：历史、收藏与索引、当前视频文本、视频助手生成结果、问答会话、动态账单及反馈、盲盒抽取记录和本地 AI 设置；只有正式 ASR 实现实际存在时，才列出本地转录稿和模型。
- 操作不修改 B 站账号、关注关系、收藏夹、评论、点赞、投币或视频内容。
- 清理期间显示进度或忙碌状态，完成后重新读取实际计数，不用乐观 UI 伪造完成。
- 部分清理失败时显示失败类别并允许重试，不把原始异常文本直接展示给用户。
- 清理结果返回部分失败后，即使配置或本地摘要的后续刷新也失败，失败类别和重试提示仍须保留；刷新错误不能覆盖已经确认的部分失败结果。
- 本地 AI 配置、当前视频主要文本选择和浮窗窗口状态共用本地设置清理窗口。已开始的写入先完成再删除；清理及全部类别回读期间拒绝或忽略新写入，最终回读完成后才恢复写入，避免已删除配置或 API Key 被迟到操作恢复。

## 8. 隐私边界

设置页明确说明：

- Bili-Bill 不读取 Cookie 文件、浏览器 profile、登录状态文件、本地 Key 文件或 `C:\Users\LittleNub\Desktop\Key.txt`。
- Bili-Bill 不上传完整观看历史、完整收藏、完整关注、完整反馈、完整笔记或完整本地数据库。
- 当前视频完整文本是明确、受控的例外：只有“当前视频 AI 助手”已开启且用户主动触发任务时，当前分 P 的主要文本才发送给配置的聊天服务。
- 本地转录音频始终保持在设备上。转录稿只有被选为主要文本来源且完整文本授权开启时，才可用于用户主动触发的当前视频 AI 请求。
- 动态账单只向 AI 发送已入选账单项的必要事实；智能收藏只发送本地预筛后的少量引用。
- Bili-Bill 不写回 B 站关系或内容。

## 9. 隐私与诊断

诊断导出可以包含：

- 功能是否开启。
- 宽泛状态、计数、时间和非敏感错误类别。
- 应用版本、浏览器版本和必要的兼容性信息。

诊断导出不得包含：

- API Key 或可恢复 Key 的值。
- Cookie、登录状态、浏览器 profile 路径或用户个人资料。
- 完整历史、收藏、关注、反馈、字幕、转录稿、问答会话或笔记正文。
- BVID、CID、内容哈希、字幕 URL、模型下载本地路径或数据库原始行。

导出前展示包含和不包含的数据类别，不自动上传诊断文件。

## 10. AI 不可用时的行为

- 当前视频：字幕页继续可用；已有摘要与亮点可标注“此前生成”后查看，没有缓存时不使用旧关键词或元数据路径伪装完整视频理解。
- 智能收藏：继续展示本地引用和来源视频。
- 动态账单：继续展示本地证据版账单。
- 视频盲盒：不依赖 AI 配置，按候选源状态正常运行。

所有功能统一提供“前往设置”入口，但不得自动跳转、自动开启开关或自动发送请求。

## 11. 验收标准

- 保存开关后切换页面、刷新和重新打开 Dashboard，UI 与持久配置一致。
- 升级场景保留服务配置，但“当前视频 AI 助手”保持关闭。
- 测试连接 payload 不包含任何本地内容数据。
- 各独立清理操作只删除目标类别，并重新显示实际计数。
- 30 天暂停列表可恢复单个 UP 主，且不修改 B 站关系。
- “清理全部本地数据”确认、失败和完成状态可用。
- 普通 UI 和诊断导出不泄漏 raw 工程字段、Key、Cookie、profile、登录状态或完整本地正文。
