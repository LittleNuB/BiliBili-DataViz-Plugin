# Bili-Bill 视频盲盒 v2 PRD

> 0.13 实现与验收以 [`PRD-0.13-release-contract.md`](./PRD-0.13-release-contract.md) 为单一有效合同。本文第 12 节提供视频盲盒详细规则；前文是 v2 历史基线，发生冲突时不得恢复“换口味”“久未观看兴趣”或不透明候选来源。

## 1. 背景

现有视频盲盒已经能从本地历史或收藏里抽出视频，并展示“换口味”“冷门收藏”“久未观看兴趣”“随机探索”等卡片。但用户反馈指出，现有定位仍像本地库存抽卡：

- 随机探索不应该局限于本地收藏或历史。
- 换口味不应该只是从本地收藏路径里换一条。
- 真正有趣的盲盒应该能连接真实 B 站视频世界。
- 随机探索和换口味需要和动态账单、智能收藏区分开。

v2 的目标是重新定义视频盲盒：它不是推荐排序，也不是收藏夹重排，而是一个透明、有来源、可解释的探索机制。

## 2. 产品定位

**视频盲盒** 是 Bili-Bill 的低压力探索入口。它帮助用户在明确的候选池中随机打开一条视频，打破最近观看惯性。

它不做平台式个性化推荐，不替代 B 站推荐流，不承诺最优排序。每个盲盒都必须说明：

- 候选来自哪里。
- 为什么属于这个盲盒。
- 是否使用了本地证据。
- 是否来自真实 B 站候选源。

## 3. v2 盲盒类型

### 3.1 随机探索

定位：从真实 B 站候选池里打开一个随机窗口。

候选来源方向：

- 当前关注 UP 的相关视频。
- 最近关注 UP 的相似 UP 视频。
- 当前常看分区的新视频。
- B 站搜索结果中的公开视频。
- UP 空间投稿。

约束：

- 不只从本地收藏或历史里抽。
- 不做个性化排序。
- 必须展示候选池来源，例如“来自 UP 空间投稿”或“来自相关视频候选”。
- 必须能打开真实 B 站视频页。

### 3.2 换口味

定位：从近期口味之外，找一条长期相关的新鲜视频。

候选来源方向：

- 长期兴趣高、近期少看的分区或标签。
- 很久没看的长期兴趣外延。
- 与长期兴趣相关但不在最近高频观看里的真实 B 站视频。
- 可结合本地历史和真实候选源。

约束：

- 不等同于随机。
- 不从近期高频口味里抽。
- 不只从收藏夹里抽。
- 必须解释“为什么是换口味”。

### 3.3 冷门收藏

定位：从用户已经收藏但很久没打开的本地视频里翻出一条。

候选来源：

- 本地收藏夹。
- 智能收藏索引。

约束：

- 这是本地盲盒，允许继续使用本地收藏。
- 应明确写“来源：本地收藏”。
- 不要伪装成 B 站真实探索。

### 3.4 久未观看兴趣

定位待定。

当前它和动态账单的“久违更新 / 换换口味 / 被淹没的关注”存在重叠。v2 需要评估：

- 如果候选来自已关注 UP 的新投稿，应归入动态账单。
- 如果候选来自真实 B 站外部候选池，可作为换口味的一种解释。
- 如果只是本地历史复盘，应保留在分析页或本地盲盒，但降低优先级。

## 4. MVP 范围

v2 MVP 分两步：

### 4.1 PRD 和候选源 spike

先完成：

- 明确四类盲盒边界。
- 调研真实 B 站候选源。
- 验证是否能安全获取候选视频。
- 确认 API 限流、登录态、分页、字段和失败状态。

### 4.2 实现两个真实候选盲盒

第一批实现：

- 随机探索：真实 B 站候选池。
- 换口味：长期兴趣外延 + 真实候选池。

保留：

- 冷门收藏：本地收藏盲盒。

暂缓：

- 久未观看兴趣的最终形态，等动态账单和候选源稳定后再决定。

## 5. B 站真实候选源候选

需要 spike 的来源：

### 5.1 相关视频

从当前视频或近期观看视频的相关视频候选中抽取。

优点：

- 更像真实探索。
- 候选通常可直接打开。

风险：

- 可能强化近期口味。
- 需要控制“换口味”时不被近期高频内容淹没。

### 5.2 UP 空间投稿

从关注 UP 或相似 UP 的公开视频中抽取。

优点：

- 来源清楚。
- 适合随机探索。

风险：

- 相似 UP 的来源不一定稳定。
- UP 投稿页分页和字段需要验证。

### 5.3 搜索结果

使用分区、标签、关键词或长期兴趣词搜索。

优点：

- 适合换口味。
- 能从本地兴趣扩展到真实 B 站。

风险：

- 搜索结果可能受平台排序影响。
- 需要避免把结果包装成 Bili-Bill 推荐排序。

### 5.4 分区新视频

从长期兴趣分区中获取新视频。

优点：

- 适合“长期兴趣但近期少看”的换口味。

风险：

- 分区接口稳定性和字段需要 spike。

## 6. 非目标

v2 不做：

- 替代 B 站推荐流。
- 个性化排序优化。
- 自动播放。
- 追踪用户是否喜欢盲盒结果并训练远端模型。
- 上传完整历史、收藏或关注。
- 写回 B 站收藏、关注或反馈。
- 把广告或商业推广作为候选源。

## 7. 用户体验

盲盒卡片必须包含：

- 盲盒类型。
- 候选来源。
- 为什么入选。
- 是否来自真实 B 站候选。
- 打开 B 站视频页按钮。
- 换一条按钮。
- 不感兴趣或少看此类的本地反馈入口，后续可选。

示例文案：

随机探索：

> 这条来自你最近关注 UP 的相邻公开视频池。Bili-Bill 没有排序推荐，只是在透明候选池里随机抽一条。

换口味：

> 你长期看过 AI 工具和开发效率内容，但最近一周主要集中在游戏剪辑。这条来自长期兴趣的真实 B 站候选，可以换个口味。

冷门收藏：

> 这条来自你的本地收藏，已经很久没有被打开。它不是外部探索，而是本地收藏回访。

## 8. 隐私边界

允许使用：

- 本地聚合兴趣事实。
- 当前视频或近期视频的公开元数据。
- B 站公开视频候选的标题、UP 名称、分区、标签、发布时间、播放页链接。

不允许：

- 读取 Cookie 文件或浏览器 profile。
- 上传完整观看历史、收藏、关注或 feedback。
- 写回 B 站。
- 把用户 mid、Cookie、token、完整本地数据库传给 AI。

## 9. 成功标准

- 用户能区分随机探索、换口味和冷门收藏。
- 随机探索至少有一个真实 B 站候选源，不再只抽本地收藏/历史。
- 换口味能解释长期兴趣和近期冷却之间的差异。
- 每张卡片都有可打开的 B 站视频链接。
- 候选失败时有清楚 fallback，不显示空卡。
- 用户不把盲盒理解为平台式个性化推荐排序。

## 10. 风险

- B 站候选源 API 不稳定。
- 搜索和相关视频结果受平台排序影响，用户可能误以为 Bili-Bill 在推荐。
- 真实候选源可能需要登录态。
- 候选质量过低会削弱盲盒趣味。
- 与动态账单的“兴趣再平衡”边界容易重叠。

## 11. 待验证问题

- 随机探索是否应该默认使用相关视频、UP 空间还是搜索结果。
- 换口味是否需要用户选择想换到哪个方向。
- 久未观看兴趣是否继续保留为盲盒类型。
- 是否需要盲盒历史，避免短时间重复抽到同一视频。
- 是否需要把盲盒反馈接入动态账单或智能收藏反馈系统。

## 12. 0.13 体验反馈后的已确认修订

本节取代第 3.2 和 3.4 中尚未稳定的“换口味”与“久未观看兴趣”产品边界，不改写前文作为 v2 历史基线的记录。

### 12.1 永久四类盲盒

0.13 起，无论当前可用历史覆盖多长，视频盲盒都保持同一组用户可见类型：

1. 随机探索：从当前已同步的本地近期观看记录中随机选择一条可公开打开的视频作为明确种子，再从该种子的真实 B 站相关视频候选池随机抽取最终视频；本地种子不是最终库存。
2. 跨区漫游：从最近高频分区之外的 B 站公开分区新视频候选池随机抽取；无近期证据时公开说明本轮随机分区。
3. 冷门收藏：从本地收藏中回访一条少有重访的已收藏视频，明确标注为本地候选。
4. UP 主考古：从已关注 UP 主的公开较早投稿中随机抽取，排除最近 7 天新投稿，不与动态账单重复。

### 12.2 跨区漫游的证据增强方向

- “跨区漫游”永久取代盲盒中的“换口味”；用户不会因历史覆盖改变而看到盲盒类型改名。
- 使用当前可用历史识别近期高频分区并做排除；更多历史如果真实可用，可以改善分区候选与解释，但不改变透明候选池内的随机抽取定位。
- 更多历史只用于减少重复、扩大分区覆盖和说明真实观察范围，不得生成偏好分数或把随机抽取改成推荐排序。
- 它可作为未来帮助用户拓宽内容暴露的方向，但 0.13 不声称或衡量“消除信息茧房”。

### 12.3 移除的重叠类型

- 盲盒不再使用“换口味”名称；已关注新投稿的兴趣再平衡留在动态账单，且不再依赖单独的长期历史栏目。
- “久未观看兴趣/本地兴趣回顾”从盲盒移除，不再作为第四张卡或历史降级卡。

### 12.4 随机探索候选生命周期

- 随机探索只从当前已同步的本地近期观看记录中选择一条带有可打开视频身份的公开记录作为种子，并在卡片中用自然中文显示本轮种子视频。
- 种子只用于请求真实 B 站相关视频候选。最终抽中的视频必须来自本轮取得的真实相关视频候选池，不能直接返回种子，也不能从本地历史或收藏中补位。
- 当前没有可用种子时，卡片显示“当前没有可用于探索的近期视频”，不读取更广的本地数据，也不切换到收藏、关注投稿或随机分区来源。
- 已有种子但真实相关视频候选为空、不可用或请求失败时，卡片显示“这次没有取得可打开的相关视频”，保留用户主动重试入口，不展示原始接口或运行时错误。
- 候选失败不得自动改用“跨区漫游”“冷门收藏”或“UP 主考古”的候选池；四类盲盒的来源边界保持稳定。

### 12.5 最小重复控制

- 四类盲盒共用一份本地“盲盒抽取记录”，只保存最近 50 个实际抽中视频的 BV 身份及维持先后顺序所需的信息，不保存候选池快照、推荐分或额外观看数据。
- 每次抽取先按对应盲盒的既定来源形成有效候选池。候选池中存在未出现在最近抽取记录中的视频时，只在这些未重复候选中随机抽取。
- 候选池中的有效视频全部已经在最近抽取记录中出现时，允许在完整有效候选池中再次随机抽取，不因重复控制制造空卡，也不自动改用其他盲盒来源。
- 抽取记录只减少短期重复，不改变候选资格、来源解释或随机顺序，不得被用作兴趣评分、推荐排序或观看证据。
- 0.13 不增加单独的重复控制开关或抽取记录管理入口；用户执行“清理全部本地数据”时一并清除该记录。
