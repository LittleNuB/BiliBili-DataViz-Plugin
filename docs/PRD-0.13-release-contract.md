# Bili-Bill 0.13 单一有效产品合同

状态：产品 grill 已完成，等待技术 spike、任务拆分与实现。

## 1. 合同优先级

本文件是 0.13 实现、验收和集成 QA 的单一有效产品合同。

发生冲突时按以下顺序处理：

1. `AGENTS.md` 的协作、安全与发布规则。
2. 本文件的 0.13 产品合同。
3. `CONTEXT.md` 的领域术语。
4. 各模块 PRD 的 0.13 详细章节。
5. 各模块 PRD 中保留的 0.12 或更早历史基线。

历史章节只用于解释设计演进，不得覆盖本合同，也不得作为恢复旧功能、旧栏目或旧文案的依据。

## 2. 发布目标

0.13 完成四条正式产品主线：

1. 当前视频助手从字幕片段罗列升级为完整主要文本驱动的摘要、亮点、问答和字幕全文体验。
2. 动态账单不再依赖不可稳定获得的长期历史，固定为基于可用证据的兴趣再平衡。
3. 视频盲盒固定为四类来源清楚的随机探索，不使用推荐排序表述。
4. 设置页统一承载 AI 授权、本地数据状态、缓存清理和暂停恢复。

本地语音转录是条件开放的实验能力。它未通过技术开放门槛时不得阻止其他正式功能发布，也不得以不完整形态进入普通 UI。

## 3. 当前视频助手

### 3.1 信息架构

- 当前视频助手使用“摘要、亮点、问答、字幕”四个一级页签。
- 摘要是默认页，每次只展示一个页签内容。
- 顶部只显示当前视频、当前分 P、主要文本来源、刷新和收起等必要状态。
- 普通用户文案使用自然中文，不显示 `fallback`、`transcript`、`confidence`、`sourceHash`、`segmentId`、`subtitle_url`、BVID、CID 或内部版本字段。

### 3.2 主要文本来源

- 主要文本来源只能是已取得正文并匹配当前分 P 的 B 站字幕，或完整完成并由用户选择的本地转录稿。
- 标题、简介、章节和元数据可以补充身份信息，但不能替代主要文本来源生成完整视频结论。
- B 站“可能存在 AI 字幕”、已探测到字幕轨道、已取得可读字幕正文是三个不同状态。
- 尚未取得字幕正文时，提示用户在播放器中手动开启“中文 AI”字幕并重新检测，同时保留本地转录入口；不得把空轨道当成可用正文。
- 查看字幕来源不改变视频助手使用的主要文本来源。只有用户点击“用于视频助手”才切换来源。

### 3.3 完整文本授权

- 设置页只保留一个默认关闭的“当前视频 AI 助手”开关，它同时是完整文本授权。
- 升级到 0.13 时不得根据旧开关自动开启该授权。
- 开启开关本身不发送任何请求。只有用户点击“生成摘要与亮点”或提交问题时，才把当前分 P 的完整主要文本发送给用户配置的聊天服务。
- 不维护模型上下文窗口能力表，不静默裁剪、分批、改用关键词检索或自动切换模型。
- 服务端拒绝过长上下文时保留用户操作内容，并用中文说明当前模型无法一次处理该文本。
- 所有完整文本操作在入口附近显示实际文本规模，以及等待时间和费用由用户配置的 AI 服务决定；不增加第二层确认框。

### 3.4 摘要与亮点

- 摘要与亮点由同一次完整文本请求生成，不重复上传和计费。
- 摘要包含 2-4 句视频概括和 3-5 个按内容顺序组织的关键要点，不在摘要中展开字幕证据。
- 亮点通常为 4-8 条关键观点、转折或演示结果，每条包含自然标题、一句概括和真实时间范围。
- 新生成结果必须整体通过证据校验；任一关键内容或亮点无法映射到当前文本版本时，整次新结果不展示，不保留看似正确的部分。
- 亮点跳转必须经过预览和用户确认，并支持返回原播放位置。
- 打开页面不自动生成。有匹配缓存时直接显示，没有缓存时等待用户点击。
- 缓存最多保留 50 个分 P 或 5 MB，任一上限先达到时按最久未访问顺序清理。

### 3.5 问答会话

- 回答必须先给出直接、完整的中文答案，再列 1-3 条来自本次参考视频的可核对引用。
- 当前视频证据不足时明确拒答，不使用通用模型知识、关键词命中或其他视频回答补齐。
- 每条引用必须匹配提交时的视频、分 P、精确文本版本和真实时间范围；任一引用无效时整次回答不展示。
- 问答使用普通、本地保存的聊天会话。会话没有固定主问题和用户可见视频分支，可以在用户切换视频后继续使用。
- 顶部显示“本次参考：当前视频《标题》”。切换视频只改变下一次提交使用的证据，不自动发送、不插入系统消息、不弹确认框。
- 每轮提交时锁定视频、分 P 和文本版本。请求期间切换页面时，结果仍写回原轮次，不得归到新视频。
- 每条有效回答底部显示“依据《视频标题》· P2 · B站字幕/本地转录”等轻量来源。来源行可打开对应视频但不直接跳时间点。
- 历史问题提供“在当前视频再问”，只把问题放回输入框；用户再次提交后才产生新请求和新轮次。
- 跨视频继续会话时只保留问题意图和术语，前一个视频的事实与引用不能支持当前回答。0.13 不做多视频综合比较。
- 每次请求发送当前分 P 的完整主要文本、最多 2000 个中文字符的滚动对话脉络、当前问题，以及仅在视频、分 P、文本版本一致时紧邻的上一轮有效问答。
- 会话最多保存 200 个或 25 MB，任一上限先达到时清理最久未访问的非当前会话；不得静默删除当前会话。

### 3.6 字幕全文

- 字幕页支持查看、播放位置跟随、本地搜索、预览确认跳转和导出。
- B 站字幕和本地转录同时存在时使用分段控件切换查看；只有一个来源时不显示无意义控件。
- 0.13 只导出当前查看来源的 TXT 和 SRT，不向普通用户提供 JSON、CSV、VTT 或内部结构字段。
- 搜索只在当前查看来源内本地执行，不调用 AI，不上传文本，不混合两个来源。

## 4. 本地语音转录实验

- 本地转录由用户主动触发，音频和未授权的转录文本不离开设备，不提供远程转录降级。
- 不设置产品层面的固定视频时长上限；启动前说明当前分 P、时长、预计耗时或风险、本地资源和可取消性。
- 首次使用在同一个确认框显示准确模型下载体积。设备最多缓存一个模型，不提供模型选择器或精度档位。
- 转录只处理当前分 P 完整音频，不依赖播放器实时从头播放；若技术方案只能实时录取一遍，则不能进入普通 UI。
- 任务切换视频、切换分 P、离开视频页或关闭页面时取消；未完成文字不展示、不保存、不导出。
- 完成稿保持原始语音语言，不提供翻译、说话人分离、身份识别、原地编辑或外部字幕导入。
- 技术开放门槛以当前视频助手 PRD 的准确度、时间对齐、长视频、取消、性能、内存和隐私指标为准。
- 未通过任一硬门槛时保留为技术验证，不阻塞字幕全文、摘要、亮点和问答交付。

## 5. 动态账单

### 5.1 固定栏目与来源

动态账单永久保持三栏：

1. 被淹没的关注：有可信关注记忆证据、近期缺席或近乎缺席，并在最近 7 天发布新视频的已关注 UP 主。
2. 收藏关联更新：既有作品存在于本地已同步收藏，并在最近 7 天发布新视频的已关注 UP 主。
3. 关注轮换：其余已关注 UP 主在最近 7 天的新视频投稿，用透明轮换扩大创作者覆盖。

- 不区分短历史模式和标准模式，不设置历史积累解锁门槛。
- 不恢复“久违更新”“换换口味”或其他需要伪长期历史的栏目。
- 较长历史只可减少重复、扩大覆盖或补强实际时间范围，不得生成推荐分或预测点击率。
- 动态账单始终是兴趣再平衡，不使用“猜你喜欢”或推荐排序表述。

### 5.2 唯一归属与轮换

- 唯一归属优先级为“收藏关联更新”高于“被淹没的关注”高于“关注轮换”。
- 同一轮每位 UP 主最多一个账单项，使用最近 7 天最新一条尚未观看投稿。
- 三栏共用全局轮换记录：从未展示优先，其次最久未展示；轮换时间相同时选择最新未观看投稿。
- 每栏最多 5 项，总计最多 15 项，不提供单栏加载更多或单栏重新生成。
- 单栏为空时使用紧凑空状态；三栏全空时使用统一空状态和统一同步/刷新入口。

### 5.3 状态与负反馈

- 保留“未打开、已打开、已消费、已处理”四种状态；不得使用“未消费”。
- “少提醒这个 UP”立即把当前项转为已处理，并在本地暂停该 UP 主进入所有动态账单栏目 30 天。
- 操作支持立即撤销，设置页支持恢复；到期后自动恢复普通资格，不获得额外优先级。
- 同一 UP 主完成第 3 次有效少提醒时只显示一次取关提示；立即撤销不计数。
- 取关提示只提供“打开 UP 主页”和“暂不处理”，不自动打开、不自动取关，也不改变当前暂停。
- AI 只为已入选账单项生成可选摘要和解释，不决定入选、归属、轮换或状态。

## 6. 视频盲盒

### 6.1 固定四类

1. 随机探索：用本地近期观看中的可打开视频作为公开种子，从其真实 B 站相关视频候选池随机抽取最终视频。
2. 跨区漫游：从近期高频分区之外的 B 站公开分区新视频池随机抽取；没有近期证据时公开说明本轮随机分区。
3. 冷门收藏：从本地收藏随机回访少有重访的视频，明确标注本地来源。
4. UP 主考古：从已关注 UP 主的公开较早投稿中随机抽取，排除最近 7 天投稿。

- 四类始终固定，不因历史覆盖变化而改名、替换或解锁。
- 每张卡说明候选来源、入选原因以及是否使用真实 B 站候选。
- 盲盒在透明候选池内随机抽取，不按偏好、互动概率或推荐分排序。

### 6.2 随机探索失败边界

- 本地种子只作为查询锚点，不能作为最终抽取结果。
- 没有可用种子时显示“当前没有可用于探索的近期视频”。
- 真实相关候选为空、不可用或请求失败时显示“这次没有取得可打开的相关视频”。
- 失败时不得用本地历史、收藏或其他盲盒来源补位，不展示原始运行时错误。

### 6.3 最小重复控制

- 四类盲盒共用最近 50 个实际抽中 BV 的本地记录。
- 有未重复候选时只在未重复候选中随机抽取；全部候选都重复时允许从完整有效候选池再次随机抽取。
- 该记录不改变来源资格或随机顺序，不作为兴趣或观看证据，也不增加独立设置项。
- 清理全部本地数据时一并清除。

## 7. 设置、本地数据与隐私

- AI 服务配置只保存服务地址、模型名、API Key 保存状态和必要连接结果；完整 Key 不在输入框回显。
- 0.13 AI 功能开关为“当前视频 AI 助手”“智能收藏问答”“动态账单解释”。视频盲盒不设置 AI 开关。
- 设置页分别显示并管理：历史、收藏与智能索引、视频文本、摘要与亮点缓存、问答会话、本地转录稿、本地转录模型、动态账单暂停、盲盒抽取记录。
- 清除操作按数据类别独立执行；“清理全部本地数据”需要二次确认并清除全部上述记录和本地 AI 设置。
- 不读取、复制或导出 Cookie 文件、浏览器 profile、登录状态文件、本地 Key 文件或 `C:\Users\LittleNub\Desktop\Key.txt`。
- 不上传完整历史、完整收藏、完整关注、完整反馈、完整笔记或无关本地数据库内容。
- 当前视频完整文本是唯一明确例外：只在完整文本授权开启且用户主动触发当前视频任务时发送当前分 P 的主要文本。
- 本地转录音频始终不发送给聊天服务。转录稿只有成为主要文本来源并满足完整文本授权时才可发送。
- 不写回 B 站关注、收藏、评论、点赞、投币或其他关系和内容。

## 8. 明确不属于 0.13

- 多视频全文综合比较或跨视频知识库。
- 语音提问、画面理解、截图问答或 OCR 视频理解。
- 实时翻译字幕、说话人分离、身份识别或 TTS 服务。
- 转录稿原地编辑、手动时间轴编辑或外部字幕导入。
- 远程转录降级、后台转录队列、断点续传或自动转录。
- 历史模式切换、栏目解锁、偏好评分、推荐排序或“猜你喜欢”。
- 云端会话同步、多 AI 服务配置或跨设备设置同步。

## 9. 发布硬门槛

- 所有正式功能通过 focused tests、`npm run typecheck`、`npm run build` 和 `git diff --check`。
- 当前视频、动态账单、视频盲盒和设置页完成 Browser/mock QA，覆盖成功、空状态、失败、刷新和跨页面状态保持。
- 当前视频时间跳转全部通过预览、确认和返回；没有伪造或错视频时间点。
- 文案扫描不得出现 `未消费`、`猜你喜欢`，普通 UI 不泄漏 raw 工程字段或运行时错误。
- AI payload 审计证明未包含禁止上传的本地数据；完整文本请求只包含当前分 P 的授权范围。
- 本地转录实验只有通过第 4 节开放门槛才进入普通 UI；失败时必须保持隐藏或明确标为技术验证。
