# Bili-Bill 0.13 可用证据策略 PRD

> 本策略是 [`PRD-0.13-release-contract.md`](./PRD-0.13-release-contract.md) 的证据子合同，不能单独用于恢复旧栏目、历史模式或推荐排序。

## 1. 背景

Bili-Bill 不能稳定获得足以区分长期与近期兴趣的观看历史。继续让“久违更新”、“换换口味”和“本地兴趣回顾”等栏目依赖长期窗口，会产生空卡片，或把短期行为误称为长期兴趣。

同时，用户可能更喜欢不依赖长期历史的栏目。如果后台积累了更多历史就自动换名、换栏目，会破坏使用习惯，也会让产品价值随数据覆盖状态反复变化。

0.13 因此不再设计“短历史/标准模式”切换，而是采用统一的可用证据策略。

## 2. 产品定位

可用证据策略要求盲盒和动态账单保持固定的用户可见结构，只使用当前真实可用的关注关系、本地收藏、近期历史和真实 B 站候选生成结果与解释。

更长历史如果真实可用，可以增强同一栏目的筛选、去重和解释，但不得解锁、替换或改名卡片，也不得让文案声称超出实际覆盖范围的长期结论。

## 3. 已确认决定

- 0.13 不再区分短历史模式和标准模式，不设置历史积累解锁门槛，也不提供模式切换器。
- 首次安装、同步状态未知、历史较短或历史较长时，用户都看到相同的盲盒类型和动态账单栏目。
- 视频盲盒永久保持四类：“随机探索”、“跨区漫游”、“冷门收藏”和“UP 主考古”。
- “跨区漫游”使用当前可用历史避开近期高频分区；没有近期证据时，公开说明本轮随机选择的 B 站分区。更多历史只能改善候选约束和解释，不改变卡片定位。
- “UP 主考古”只从已关注 UP 主的公开较早投稿中抽取，不使用最近 7 天新投稿，以避免与动态账单重复。
- 动态账单永久保持三栏：“被淹没的关注”、“收藏关联更新”和“关注轮换”。三栏都只处理已关注 UP 主在动态内容窗口内的新视频投稿。
- “被淹没的关注”使用稳定关注关系与当前可用近期窗口中的缺席事实，不要求强长期观看正反馈，也不应被长期观看门槛拦截。
- 已关注时间未知时，“被淹没的关注”仍可由特别关注、Bili-Bill 连续观察该关注关系至少 30 天，或当前近期窗口之前的真实本地观看记录支撑。至少满足一项才可入选；都不满足时进入“关注轮换”，不能把普通关注伪装成“被淹没”。
- “收藏关联更新”展示本地收藏过其既有作品的已关注 UP 主新投稿；收藏只证明明确的兴趣关系，不作为推荐排序分数。
- “收藏关联更新”使用全部已同步的 B 站视频收藏，包括默认收藏夹和其他已同步收藏夹；同一 BV 出现在多个收藏夹时只计算一次。
- 智能收藏整理不是“收藏关联更新”的入选前提，也不是另一套收藏来源。已有智能分类只能辅助生成自然解释，不得决定入选或排序。
- 收藏同步不完整时可以使用已同步条目，但候选来源只能表述为“来自本地已同步收藏”，不得暗示已经覆盖全部收藏。
- “关注轮换”覆盖其余已关注 UP 主的近期新投稿，以创作者覆盖广度为目标，不预测点击概率，也不使用“猜你喜欢”表述。
- “关注轮换”跨次生成时使用最小本地轮换记录：从未进入过动态账单的 UP 主优先，其次是最久未进入动态账单的 UP 主。轮换记录只保存完成该顺序所需的创作者标识与最近展示时间，不作为观看、消费或兴趣评分证据。
- 同一份全局轮换记录也用于“收藏关联更新”和“被淹没的关注”。先按证据和唯一归属优先级确定栏目，再在各栏中优先从未展示、其次最久未展示的 UP 主；轮换时间相同时选择最新的未观看投稿。
- 当前合格 UP 主都已展示后，“关注轮换”从最久未展示者继续循环；只要动态内容窗口内仍有尚未观看的合格投稿，就不因人为冷却期制造空栏目。只有候选池确实为空时才显示空状态。
- 同一投稿只进入一个动态账单栏目，唯一归属优先级为“收藏关联更新”高于“被淹没的关注”高于“关注轮换”。命中更高优先级后，从后续栏目候选池中移除。
- 同一轮动态账单中，每位 UP 主最多出现一次。先为每位 UP 主选择动态内容窗口内最新一条尚未观看的投稿，再按上述优先级唯一归栏；该 UP 主的其余投稿本轮不再铺卡。
- 单个固定栏目没有候选时，只显示紧凑的“本轮暂无……”状态，不保留占满页面高度的空栏；其他有内容的栏目自动扩展。
- 三栏都没有候选时，页面只显示一个统一空状态，并提供统一的同步或刷新入口。动态账单不提供单栏“重新生成”，因为栏目不是随机抽取。
- 每轮动态账单每栏最多展示 5 项，总计最多 15 项；不足 5 项时按实际候选展示。0.13 不提供单栏“加载更多”，下一次统一刷新时继续按轮换规则选择候选。
- 0.13 保留账单项的“未打开、已打开、已消费、已处理”状态，以及打开视频、标记已处理和“少提醒这个 UP”动作。
- 主题级“少提醒”从动态账单移除；固定三栏不再由主题栏目驱动，不新增主题偏好画像。重复的 UP 主级少提醒仍可触发低压力取关提示，但不会自动修改 B 站关系。
- AI 仍只负责可选的摘要与解释，不参与入选、唯一归属或轮换顺序；AI 未启用或失败时继续展示完整的本地证据版账单。
- “久违更新”、“换换口味”和“本地兴趣回顾”不再作为 0.13 用户可见栏目。真实可用的较长历史可以增强固定栏目，但不会使这些旧栏目重新出现。
- 较长历史只允许用于减少重复、扩大创作者或分区覆盖，以及补强可核对的时间范围说明。只有实际覆盖支持时，才能显示“本地记录中近 60 天未观看”等明确时间结论；否则使用不带伪造时长的近期事实。
- 较长历史不得因“过去看得多”给候选增加推荐分、预测点击率或改变为偏好排序，也不得恢复已移除的长期历史栏目。
- 用户不需要看到历史模式、解锁进度或栏目切换提示。

## 4. 不变的边界

- 动态账单仍然是“兴趣再平衡”，不使用“猜你喜欢”或推荐排序表述。
- 真实 B 站候选与本地收藏、本地历史必须分别标明，不混成不明来源的候选池。
- 普通用户文案使用自然中文，不显示内部状态码、原始字段或调试错误。
- 不因历史不足而扩大本地隐私数据读取范围。
- 不能用“长期”、“久违”或“冷却”等文案描述当前证据无法支持的时间关系。

## 5. Grill 状态

动态账单的 0.13 固定栏目、候选来源、归属、轮换、密度、空状态与既有闭环边界均已确认。
