# 智能收藏知识库 PRD

## 1. 背景

0.12 内容助手计划要求把智能收藏从“分类浏览 + 模糊搜索”推进到“问答式个人视频知识库”。主线目标不是扩展 B 站推荐或重排收藏夹，而是让用户能围绕自己已经同步到 Bili-Bill 的收藏提问，并得到可追溯、可点击、可解释的收藏视频引用。

当前仓库已经具备智能收藏同步、智能索引、同步完整性诊断、本地收藏问答、`citedVideos` 引用视频和可选 AI 综合回答。本 PRD 用于把这些能力收束成 0.12 的产品边界，并为后续 #137“当前视频 x 智能收藏联动”定义可实现但不越界的接口方向。

本 PRD 是 docs-only。它不实现新的 message action、DB schema、AI 调用、Dashboard UI、Popup UI、content script 或 Smart Favorites runtime。

## 2. 产品定位

智能收藏知识库是 Bili-Bill Dashboard 和后续助手入口里的收藏问答能力。它回答的是“我已经同步到本地的收藏里，有哪些视频与这个问题相关”，并用引用视频说明依据。

它可以回答收藏库问题，例如：

- “我收藏过讲库尔斯克的二战视频吗？”
- “找我收藏里和时间管理相关的视频。”
- “有没有同一个 UP 主讲过类似主题的收藏？”
- “这些候选为什么和我的问题相关？”

它不回答当前视频正文问题，也不替代当前视频助手的证据链。当前视频问答必须继续只使用当前视频证据，例如当前 BVID/CID、标题、简介、分 P、章节、字幕片段、当前视频知识节点和经过当前视频身份校验的本地候选。

## 3. 用户故事

1. 作为已经同步收藏夹的用户，我想用自然语言询问收藏库，所以我不需要记住准确标题或收藏夹路径。
2. 作为经常收藏学习视频的用户，我想看到答案引用了哪些收藏视频，所以我能判断回答是否可靠。
3. 作为收藏夹很大的用户，我想知道回答是否只覆盖当前已同步收藏，所以我不会误以为 Bili-Bill 已检查全部收藏。
4. 作为未生成智能索引的用户，我想仍能得到基于标题、简介、UP、分区、标签和收藏夹名的本地结果，所以 AI 不可用时功能不空转。
5. 作为 AI 未配置或禁用的用户，我想看到本地引用结果和原因，所以我不需要为了基础找回能力上传数据。
6. 作为正在看当前视频的用户，我想在当前视频助手里看到“相关收藏”分区，所以我能延伸阅读相近主题。
7. 作为正在问当前视频问题的用户，我想系统明确区分当前视频答案和相关收藏，所以收藏结果不会被误当成当前视频内容证据。

## 4. 允许的数据源

智能收藏知识库第一版允许使用：

- 收藏视频元数据：BVID/avid、标题、简介、UP 名称、原收藏夹、分区、标签、封面、时长、发布时间、收藏时间和同步时间。
- 智能收藏索引：分类路径、摘要、关键词、别名、可检索文本、索引状态、索引模型和索引时间。
- 同步覆盖信息：B 站报告数量、本地保存数量、同步诊断数量、问题收藏夹数量和同步完整性状态。
- 索引覆盖信息：已索引、索引失败、待索引、索引过期、索引缺失等聚合状态。
- 当前视频 hints：只在 #137 的“查找相关收藏”入口中作为检索 hint 使用，例如当前视频标题、UP、分区、标签或当前视频问题关键词。

第一版不使用：

- 字幕、弹幕、评论、音频、画面、OCR 或完整视频正文。
- 完整观看历史、完整关注列表、完整 feedback 记录或完整本地数据库。
- Cookie、key、浏览器 profile、Bilibili 登录态文件、用户个人资料文件或本地密钥文件。

## 5. 回答结构

每次收藏问答必须返回一个有边界的回答对象，而不是无来源生成文本。

必须包含：

- `answerType`：`retrieval_answer`、`candidate_list`、`no_result` 或 `insufficient_evidence`。
- `answer`：面向用户的简短中文回答。
- `confidence`：只表示本次回答证据强度，不表示视频质量。
- `evidenceSummary`：说明使用了哪些本地字段，以及是否存在索引缺失或索引过期。
- `status`：包含同步覆盖和索引覆盖状态。
- `citedVideos`：回答引用的收藏视频列表。没有引用时只能是 no-result 或证据不足状态。
- `synthesis`：可选 AI 综合状态；AI 不可用时仍保留本地引用结果。

### 5.1 Cited videos

`citedVideos` 是智能收藏知识库的核心证据单位。每条引用视频必须包含足够用户判断的最小字段：

- `bvid` 或 `avid`
- 标题
- UP 名称
- 原收藏夹名称
- 智能分类路径
- B 站视频链接
- 命中原因
- 来源字段
- 证据强度
- 一句话证据说明
- 本地 evidence hits
- 本地评分
- 同步时间
- 索引时间，如存在

引用视频只能来自本地检索 top N。AI 可以组织语言，但不能新增、替换、暗示或引用 `citedVideos` 之外的视频。

### 5.2 回答类型

| 类型 | 触发 | 允许行为 | 禁止行为 |
| --- | --- | --- | --- |
| `retrieval_answer` | 至少一个引用视频有中高证据 | 回答“当前已同步收藏中最相关的是这些”，并引用视频 | 声称覆盖用户全部收藏或完整视频正文 |
| `candidate_list` | 有候选但证据弱或分散 | 列出候选、命中原因和缺失项 | 给出唯一确定结论 |
| `no_result` | 本地候选为空 | 说明当前已同步收藏中未找到，并建议同步、索引或改写问题 | 编造用户可能收藏过的未引用视频 |
| `insufficient_evidence` | 用户询问字幕、正文、观点细节或完整内容，但只有元数据/索引 | 说明当前切片不能回答正文问题，可展示相关候选 | 根据标题或简介生成视频正文结论 |

## 6. 同步覆盖状态

收藏同步可能因为 API 分页、访问失败、数量差异、达到页数上限或资源过滤而不完整。智能收藏知识库必须把同步覆盖状态带入回答。

推荐状态：

| 状态 | 判定 | 用户可见原则 |
| --- | --- | --- |
| 同步完整 | 已有诊断且所有诊断为 complete | 可以写“在本地已同步收藏中” |
| 同步不完整 | 任一收藏夹诊断为 incomplete，或存在 page error、delta、has_more after stop、max pages reached | 必须写“在当前已同步收藏中”，不能写“全部收藏中没有” |
| 尚未同步 | 本地没有收藏快照 | 提示先同步收藏夹，不发 AI 请求生成收藏结论 |

回答中可以展示聚合覆盖摘要，例如“B站报告 200 条，本地保存 180 条，已索引 150 条，失败 5 条，待索引 25 条”。AI payload 不应包含具体问题收藏夹名称、mediaId、错误详情或完整诊断列表。

## 7. 索引覆盖状态

智能收藏知识库必须区分收藏同步覆盖和智能索引覆盖。

推荐状态：

| 状态 | 触发 | 行为 |
| --- | --- | --- |
| 索引可用 | 已索引项可用于检索 | 使用分类路径、摘要、关键词、别名参与召回和解释 |
| 索引缺失 | 本地有收藏，但已索引数量为 0 | 使用元数据检索，并提示智能索引字段不可用 |
| 索引过期 | 收藏同步时间晚于索引时间，或存在待索引/失败项 | 继续使用元数据和可用索引，但提示结果可能不完整 |
| 索引部分失败 | 存在 failed items | 不隐藏失败；提供重试失败项或重新生成索引入口 |

索引覆盖不等于收藏同步覆盖。同步完整但索引缺失时，回答仍只能说“本次只使用元数据”；同步不完整但索引可用时，回答仍不能声称覆盖全部收藏。

## 8. UX 状态

智能收藏知识库的用户可见状态必须覆盖：

| 状态 | 用户可见行为 |
| --- | --- |
| 同步不完整 | 标注回答只基于当前已同步收藏，展示聚合覆盖摘要和同步入口 |
| 索引过期 | 标注智能索引可能过期或不完整，展示生成/重试索引入口 |
| AI 未配置 | 不发 AI 请求，展示本地引用结果，并引导到设置页配置 |
| AI 禁用 | 不发 AI 请求，展示本地引用结果，并说明可在设置页启用 |
| AI 失败 | 保留本地候选和引用，展示失败摘要和重试入口 |
| AI 输出被拒绝 | 保留本地引用结果，说明 AI 综合未通过引用边界检查 |
| 本地证据结果 | 明确标注本地引用回答、引用视频和命中字段 |
| 无结果 | 显示没有找到匹配收藏，建议同步、生成索引或改写问题 |
| 低证据 | 优先展示候选列表，不写确定答案 |

普通 UI 应使用自然中文，不展示 raw status code、hash、内部字段名或工程化英文。审计字段可在开发日志或测试里保留，但不要进入普通用户主路径。

## 9. 隐私 payload 边界

AI 请求必须本地检索先行，只上传 top N cited favorites 的最小字段。推荐最大值为 8 条，后续实现可按性能和模型上下文进一步收紧。

允许上传到 AI 的字段：

- 用户问题的截断文本
- 同步覆盖摘要：complete、diagnosticsCount、problemFolders、coverageStatus
- 索引覆盖摘要：indexedItems、failedItems、pendingItems、staleItems、indexMissing、staleIndex
- 可用来源开关：favoriteMetadata、smartIndex、transcript=false、contentText=false
- top N `citedVideos` 的最小字段：BVID/avid、标题、UP 名称、原收藏夹名称、智能路径、链接、命中原因、来源字段、证据强度、证据说明、有限 evidence hits、本地评分
- 安全规则

禁止上传：

- 完整收藏库
- 完整收藏夹结构
- 未命中项全集
- 完整观看历史
- 完整关注列表
- 完整 feedback 记录
- 完整 IndexedDB dump 或导出文件
- Cookie、key、浏览器 profile、Bilibili 登录态文件、用户个人资料
- `C:\Users\LittleNub\Desktop\Key.txt` 或任何本地密钥路径
- 具体同步错误详情、私有收藏夹 mediaId、完整诊断列表

AI 输出必须经过引用边界 guard。任何引用了 payload 之外的视频、标题或 BVID/avid 的输出都应被拒绝，并回退到本地引用结果。

## 10. 与当前视频助手的边界

当前视频助手回答当前视频问题时，不能使用智能收藏结果替代当前视频证据。当前视频答案必须继续只基于当前视频身份匹配后的证据：

- 当前 BVID/CID/page
- 当前视频标题、简介、分 P、章节
- 当前视频字幕片段或知识节点
- 当前视频本地检索候选
- 当前视频 source tier 和可用来源状态

智能收藏知识库可以参与当前视频助手，但只能作为独立的“相关收藏”分区：

- #137 可以把当前视频标题、UP、分区、标签、简介摘要或用户问题作为检索 hint。
- #137 可以展示“相关收藏”卡片，引用收藏视频并提供打开入口。
- #137 必须在 UI 中把“当前视频回答”和“相关收藏”分开。
- #137 必须标注相关收藏来自“当前已同步收藏”。
- #137 在同步不完整或索引过期时必须展示覆盖限制。
- #137 不能把相关收藏写进当前视频回答的证据片段。
- #137 不能因为找到相关收藏，就声称当前视频讲过某个概念。
- #137 不能自动跳转、自动播放或写回 B 站收藏夹。

如果用户在当前视频助手里问“这个视频有没有讲 X”，答案仍应来自当前视频证据。相关收藏只能作为后续阅读：“当前视频证据不足；你当前已同步收藏中有这些相关视频。”

## 11. 非目标

本 PRD 不做：

- 不改 Smart Favorites runtime。
- 不改 Dashboard、Popup、public、content script 或 background 功能代码。
- 不新增 message action。
- 不改 DB schema。
- 不新增 AI 调用。
- 不实现 #137。
- 不创建 GitHub issue。
- 不读取、复制或记录 Cookie、key、browser profile、Bilibili 登录态文件或本地密钥文件。
- 不做字幕、弹幕、评论、音频、画面或完整视频正文问答。
- 不把智能收藏包装成观看引导型推荐流。

## 12. 测试与验收建议

后续 implementation issue 应覆盖以下外部行为：

- 收藏库问题能返回 `retrieval_answer` 和至少一个 `citedVideos`。
- 低证据问题返回候选列表，不写唯一确定答案。
- 无结果问题返回 no-result，不编造引用。
- 用户询问字幕、正文或完整内容时返回证据不足，并说明第一版只使用收藏元数据和智能索引。
- 同步不完整时，回答限定为“当前已同步收藏”，并展示覆盖摘要。
- 索引缺失或索引过期时，仍有本地元数据 fallback。
- AI 未配置、禁用、失败、输出被拒绝时，本地引用结果仍可见。
- AI payload allowlist 不包含完整收藏库、完整收藏夹结构、未命中项全集、完整历史、完整关注、完整 feedback、Cookie、key、profile 或本地敏感路径。
- #137 联动中，当前视频回答和相关收藏分区分开渲染；相关收藏不能作为当前视频答案证据。

## 13. 后续 implementation issue 切片建议

以下只是实现切片建议，不在本任务中创建 issue：

1. Smart Favorites knowledge-base UX copy pass：把 Dashboard 智能收藏问答状态文案统一为“本地引用回答 / 引用视频 / 覆盖限制 / AI 综合状态”。
2. Coverage guard QA：补足同步不完整、索引缺失、索引过期和 failed/pending index 的端到端 mock。
3. Cited videos rendering polish：完善引用卡片的信息层级、展开证据和打开视频入口。
4. AI synthesis rejection UX：把引用边界拒绝、AI 失败和本地 fallback 的用户文案做成同一套状态组件。
5. #137 related favorites entry：当前视频助手新增“相关收藏”分区，传入当前视频 hints，复用智能收藏本地检索和 cited videos，不改当前视频回答证据源。
6. #137 boundary tests：验证当前视频回答没有读取或引用收藏结果；相关收藏分区单独展示并标注“当前已同步收藏”。
7. Privacy payload audit extension：继续复用 `smartFavoriteQaPayloadContract`，为 #137 related favorites payload 增加 allowlist 或复用现有 top-N cited videos payload。
8. Local metrics：只记录 no-result、低证据、引用点击、AI fallback、同步覆盖风险等聚合状态，不上传完整收藏内容。

## 14. 验收标准

- PRD 明确智能收藏可以回答收藏库问题。
- PRD 明确当前视频问答不能用收藏库替代当前视频证据。
- PRD 定义 `citedVideos` 的字段和引用边界。
- PRD 定义同步覆盖状态、索引覆盖状态、低证据回答和无结果回答。
- PRD 定义 AI 未配置、禁用、失败、输出被拒绝和本地证据结果的 UX 状态。
- PRD 定义隐私 payload 最小化边界：只上传 top N cited favorites 的最小字段，不上传完整收藏库、完整收藏夹结构、未命中项全集、历史、关注、feedback、Cookie、key 或 profile。
- PRD 定义 #137 当前视频 x 智能收藏联动边界，并给出后续切片建议。
- 本任务的 diff 只包含 docs 下 PRD 文档，不包含 runtime 改动。
