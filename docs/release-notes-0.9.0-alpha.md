# Bili-Bill 0.9.0-alpha 内测发布说明

发布日期：2026-06-07

`0.9.0-alpha` 是 Bili-Bill vNext 的内测版本。这个版本已经从原来的数据可视化插件方向升级为 **Bili-Bill**：一个面向 B 站高频用户的个人内容账单工具，用于归档观看历史、理解消费结构、整理收藏内容，并在打开关注动态前提供动态账单。

本版本仍处于 alpha 内测阶段，适合愿意手动加载扩展、观察数据口径、反馈体验问题的用户使用。它不是 Chrome Web Store 正式发布包，也不会自动迁移或修改你的 B 站关注关系。

## 版本重点

### Bili-Bill shell 与品牌

- 扩展名、Dashboard 外壳和主要入口统一为 Bili-Bill。
- Dashboard 使用新的侧边导航承载总览、行为分析、创作者、智能收藏、动态账单等模块。
- Popup 改为独立持久小窗，点击扩展图标会打开或聚焦窗口，便于长时间同步时查看进度。

### 观看历史分析

- 使用 B 站历史接口作为跨设备主数据源，覆盖 PC、手机、平板等观看历史。
- 使用本机网页播放器事件作为 PC 实测增强，帮助修正本机观看时长、连续观看天数和设备分布。
- 历史记录保存到本地 IndexedDB，Dashboard 可展示自然周、自然月、命中记录数、本地历史覆盖范围、设备分布、连续观看时间段等分析结果。
- 支持手动全量同步、后台增量同步、同步取消和 JSON/CSV 本地导出。

### 智能收藏夹

- 可同步当前 B 站账号的收藏夹与收藏视频元数据到本地。
- 可配置 OpenAI 兼容模型，为收藏视频生成分类路径、摘要、关键词和可检索别名。
- 支持分类树下钻和自然语言搜索，例如用模糊描述找回收藏内容。
- 智能收藏夹不会创建、移动、删除或重命名 B 站原收藏夹。

### 动态账单

动态账单是本版本的主要新增能力。它面向 **兴趣再平衡**：帮助你在打开 B 站关注动态前，看见那些可能被近期口味覆盖、但仍值得重新考虑的已关注视频投稿。

动态账单不是实时个性化推荐排序，也不是点击预测系统。它不替代 B 站动态页，不改写 B 站原生排序，也不以提升点击率或观看时长为目标。第一版只覆盖已关注 UP 的视频投稿动态。

## 动态账单三栏

### 久违更新

展示过去有明显观看正反馈、但近期冷却的 UP 的新视频。它用于提醒你：某条历史兴趣线可能已经很久没有被打开，但现在有新的投稿值得回访。

典型依据包括长期窗口内的观看记录、近期窗口内的冷却情况、最近 7 天内的新投稿，以及是否已排除近期看过的同一视频。

### 换换口味

展示长期喜欢、但近期消费占比下降的分区或标签里的新视频。它用于提醒你：最近的观看可能过于集中，可以从已关注 UP 的新投稿里切换到另一条长期兴趣。

第一版主要基于 B 站分区、标签和本地归一化类目判断，不使用 AI 自创主题簇决定入选。

### 被淹没的关注

展示有稳定关注关系、但近期几乎没有消费的 UP 的新视频。它与“久违更新”的区别是：不要求这个 UP 在历史观看中一定有强正反馈，关注关系本身也是一种长期品味线索。

当关注时间不可用时，页面会降级展示“已关注，关注时长未知”一类说明，不伪造关注时长。

## AI 说明与本地 fallback

AI 说明是可选增强，不是动态账单可用性的前提。

- 本地规则决定账单项是否入选和展示顺序。
- AI 只用于为已入选账单项生成摘要、入选解释、观看角度和关键词。
- 未配置 AI、禁用 AI 或 AI 请求失败时，动态账单仍会展示本地证据版 fallback。
- AI 的 `confidence` 只表示模型对解释质量的自评，不参与入选规则或排序。

如果你不填写 OpenAI 兼容 API Key，仍然可以使用观看历史分析、智能收藏夹同步、动态账单本地证据和基础账单操作。

## 隐私边界

Bili-Bill 0.9.0-alpha 的隐私边界如下：

- 不上传完整观看历史。
- 不上传完整关注列表。
- 不上传 Cookie。
- 不上传用户 mid。
- 不上传个人资料。
- 不上传 feedback 记录。
- 不写回 B 站关注关系。
- 不提供插件内自动取关、批量取关或批量修改关注设置。

当你主动启用 AI 能力时，AI 请求只应包含当前生成所需的最小上下文，例如入选视频的标题、简介、UP 名称、分区、标签、时长、发布时间、栏目名称和紧凑本地证据事实。动态账单与智能收藏夹的本地规则、状态、反馈和配置默认保存在浏览器本地存储中。

## 升级与安装说明

### 从旧版本或开发分支升级

1. 在同一个浏览器 Profile 登录 B 站。
2. 拉取或切换到 `0.9.0-alpha` 对应代码。
3. 运行：

   ```bash
   npm install
   npm run build
   ```

4. 打开 Chrome/Edge 的 `chrome://extensions`。
5. 开启“开发者模式”。
6. 如果是首次安装，点击“加载已解压的扩展程序”，选择项目的 `dist/` 目录。
7. 如果已经安装过开发版，点击扩展卡片上的“重新加载”。
8. 打开 Popup，按需同步观看历史；进入 Dashboard 后可使用智能收藏和动态账单。

### 版本号说明

- `package.json` 对外版本为 `0.9.0-alpha`。
- Chrome MV3 manifest 的 `version` 为 `0.9.0`。
- manifest 的 `version_name` 为 `0.9.0-alpha`，用于向用户暴露 alpha 预发布标识。

## 已知限制

- 本版本是内测版本，仍建议使用开发者模式加载 `dist/`，尚未创建 GitHub Release、正式 tag 或商店安装包。
- B 站历史、收藏、关注关系和动态接口的返回范围由 B 站决定；如果接口不返回更早数据，Bili-Bill 无法凭空恢复。
- 扩展安装前未采集到的本机 PC 播放器心跳无法补回，只能从安装后开始增强本机观看时长口径。
- 默认历史保留策略和老用户已有配置可能不同；如果本地历史不足长期窗口，动态账单的长期兴趣判断会相应变短。
- 动态账单第一版只覆盖已关注 UP 的视频投稿动态，不覆盖图文动态、转发动态、直播提醒、专栏或番剧追番提醒。
- 动态账单不会改写 B 站动态页排序，也不会在 B 站页面内注入完整替代流。
- AI 能力依赖用户自行提供 OpenAI 兼容 API Key；API Key 当前明文保存在本地 `chrome.storage.local`。
- AI 请求失败、模型返回异常或浏览器 MV3 Service Worker 中断时，AI 说明可能缺失，但本地证据 fallback 仍可使用。
- 生产构建目前可能出现既有 Vite large chunk warning，主要来自图表主题相关 chunk 体积偏大；这不是本次内测发布的功能阻塞项，后续可通过拆分依赖或延迟加载优化。

## 内测反馈建议

反馈动态账单时，建议重点描述：

- 是否能理解动态账单是兴趣再平衡，而不是实时个性化推荐排序或点击预测。
- 三栏中哪一栏最容易理解，哪一栏看起来像误报。
- AI 说明缺失或失败时，本地证据是否足够支撑判断。
- “少提醒这个 UP / 少提醒这个主题”和取关提示是否让你明确知道：Bili-Bill 不会替你修改 B 站关注关系。
