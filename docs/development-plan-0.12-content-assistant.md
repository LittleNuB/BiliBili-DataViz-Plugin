# Bili-Bill 0.12 内容助手开发计划

## 1. 版本目标

0.12 的目标是把 Bili-Bill 从“多个可用功能页”推进到“个人内容助手”：

- 当前视频助手从字幕检索器升级为当前视频 Agent。
- 智能收藏从分类浏览升级为个人视频知识库入口。
- 视频盲盒从本地抽卡升级为真实 B 站探索。
- AI Key、本地数据和隐私边界迁入全局设置页。

本计划是开发准备文档，不直接代替每个 issue 的详细实现说明。

## 2. 工作流约束

开发任务必须遵守：

- 每个 issue 使用干净 sibling worktree。
- Draft PR 到 `main`。
- 主 Agent 审查后再转 ready 和合并。
- 不读取 `C:\Users\LittleNub\Desktop\Key.txt`。
- 不读取或复制 Cookie 文件、浏览器 profile、Bilibili 登录态文件。
- 不上传完整历史、完整收藏、完整关注或 feedback。
- 不写回 B 站。
- 普通用户 UI 使用中文，不泄漏 raw 字段、hash、URL、token 或状态码。

## 4. 第一批：基础与当前视频 Agent

### 4.1 全局设置页 MVP

目标：

- 左侧新增“设置”。
- 迁移 AI Key、Base URL、模型名、测试连接。
- 添加 AI 功能开关。
- 添加隐私与本地数据说明。
- 智能收藏页只保留 AI 状态和“前往设置”。

验收：

- 当前视频、智能收藏、动态账单的 AI 未配置提示都指向设置页。
- API Key 不明文展示完整值。
- 不改变现有 AI 调用行为。
- 关闭功能开关时，对应功能走本地证据 fallback。

### 4.2 当前视频查询改写

目标：

- 用户输入自然语言或英文概念时，能召回中文字幕中的同义表达。

第一版词表：

- `subagent`、`sub-agent`、`子代理`、`子智能体`、`多代理`、`multi-agent`。
- `context window`、`上下文窗口`、`长上下文`、`1M context`、`100万上下文`、`一兆上下文`。
- `tool use`、`工具调用`、`函数调用`、`function calling`。

实现建议：

- 纯函数模块放在 `src/shared/` 或 background current-video 相关模块。
- 输出扩展词和命中原因。
- 不引入 embedding 作为第一版前提。

验收：

- `subagent` 能命中含“子代理/子智能体”的字幕片段。
- `1M context` 能命中“100万上下文/一兆上下文/长上下文”。
- UI 展示“已扩展相关表达”，但不展示内部规则名。

### 4.3 当前视频问答 v1

目标：

- 把“检索片段”体验升级为“回答问题 + 引用片段”。

输出：

- 回答状态。
- 简短回答。
- 证据片段。
- 跳转操作。

实现建议：

- 先用本地候选生成本地回答模板。
- AI 启用时只基于 top N 候选片段整理回答。
- 使用 payload audit guard。
- AI 输出必须被 schema guard 校验。

验收：

- 问“有没有关于 subagent 的介绍？”时，先回答有/没有/证据不足。
- 回答必须引用字幕证据。
- 没有字幕时不生成完整回答。
- 不生成新的时间点。

### 4.4 页内助手 UX polish

目标：

- 降低信息堆叠感。
- 修正用户可见文案。
- 强化当前页工作流。

建议改动：

- 输入框占主路径，文案改为“问这个视频，或描述想跳到的片段”。
- 摘要、问答、知识节点可以做 tabs 或折叠区。
- “页面正文”和“字幕正文”分开命名。
- 面板支持更清楚的收起状态。
- 跳转后状态显示目标时间和返回时间。

验收：

- 用户不需要打开 Dashboard 即可完成单视频问答和跳转。
- 普通 UI 无 `fallback`、`transcript`、`confidence` 等工程化英文。
- 窄屏不遮挡关键播放器控件。

## 5. 第二批：智能收藏知识库

### 5.1 智能收藏知识库 PRD

目标：

- 把智能收藏从分类树升级为问答式个人视频知识库。

需要定义：

- 问答输入。
- 回答结构。
- 引用收藏视频。
- 同步不完整时的状态文案。
- 与当前视频助手的边界。

关键边界：

- 智能收藏可以回答收藏库问题。
- 当前视频问答不能用收藏库替代当前视频证据。
- “查找相关收藏”是当前视频的延伸阅读，不是当前视频回答依据。

### 5.2 当前视频 x 智能收藏联动

目标：

- 在当前视频助手中提供“查找相关收藏”。
- 使用当前视频标题、UP、标签、摘要或用户问题作为检索 hint。
- 返回收藏视频引用和打开入口。

验收：

- 当前视频问答和相关收藏结果分区清楚。
- 收藏结果明确来自“当前已同步收藏”。
- 同步不完整时提示范围限制。

## 6. 第三批：视频盲盒 v2

### 6.1 B 站真实候选源 API spike

目标：

- 验证真实候选池是否可行。

候选接口方向：

- 相关视频。
- UP 空间投稿。
- 搜索结果。
- 分区新视频。

输出：

- `docs/spikes/video-blind-box-candidate-sources.md`
- 每个来源的字段、分页、登录态、失败状态和隐私边界。
- 是否进入 MVP 的结论。

验收：

- 至少一个来源可作为随机探索候选池。
- 至少一个来源可作为换口味候选池。
- 不读取 Cookie 文件或浏览器 profile。

### 6.2 随机探索真实候选池 MVP

目标：

- 随机探索不再只从本地收藏/历史抽。

候选：

- 从 spike 证明可用的真实 B 站候选池中抽。

验收：

- 卡片展示真实来源。
- 打开 B 站视频页可用。
- 不写成推荐排序。
- 候选失败时有 fallback。

### 6.3 换口味真实候选池 MVP

目标：

- 找长期相关、近期少看的新鲜真实视频。

输入：

- 本地长期兴趣。
- 近期观看冷却。
- 真实 B 站候选源。

验收：

- 显示“为什么是换口味”。
- 不从近期高频兴趣里抽。
- 不只从收藏夹里抽。

## 7. Onboarding 与隐私说明

目标：

- 降低首次使用门槛。
- 统一解释本地证据和隐私边界。

建议入口：

- 设置页顶部。
- 空状态页。
- 当前视频助手字幕不可用状态。

步骤：

1. 同步观看历史。
2. 同步收藏夹。
3. 配置 AI。
4. 打开一个 B 站视频并开启中文 AI 字幕。
5. 试一次当前视频问答。

## 8. 验证策略

每个开发 PR 至少：

- `npm run typecheck`
- `npm run build`
- 对应 focused tests。
- `git diff --check`
- 项目禁用状态词和禁用推荐定位词扫描。
- 用户可见 raw 字段扫描。

当前视频相关 PR 还应覆盖：

- 无字幕。
- 字幕缓存成功。
- 低置信候选。
- 预览不 seek。
- 确认后才 seek。
- 返回原位置。
- 视频身份不匹配时阻止。

真实 B 站候选源 PR 还应覆盖：

- 未登录或访问失败。
- 候选为空。
- API 限流。
- 真实链接可打开。

## 9. 发布建议

0.12 可以拆为两个 alpha：

### 0.12.0-alpha

- 全局设置页。
- 当前视频查询改写。
- 当前视频问答 v1。
- 页内助手 UX polish。

### 0.12.1-alpha

- 智能收藏知识库 PRD 或 MVP。
- 视频盲盒 PRD。
- B 站候选源 spike。

真实盲盒候选池实现建议在 spike 之后进入 0.13 或 0.12.2-alpha，不要和当前视频 Agent 抢同一轮风险预算。

## 10. 待确认问题

- 是否允许当前视频问答使用 AI 默认开启，还是默认关闭。
- 查询改写是否只用本地词表，还是允许 AI query rewrite。
- 盲盒真实候选是否允许使用 B 站搜索结果。
- 设置页是否需要清理全部本地数据。
- 智能收藏知识库是否需要独立 PRD 先行。
- 0.12 是否要发布 alpha，还是先作为 main 上的连续迭代。
